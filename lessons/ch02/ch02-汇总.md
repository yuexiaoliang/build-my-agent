# 第 02 章汇总 · 工具契约

- 日期：2026-09-14
- 本章核心问题：模型请求如何成为合法行动？
- 章末 tag：`ch02`；各步细节见 02.1–02.4 卡片

## 每一步给出的部分答案

- **02.1 请求形状**：工具定义（name / description / JSON Schema）放在 `request.tools`；模型用 `tool_calls` 请求行动，`arguments` 是 JSON 字符串；模型只能请求，不能执行。
- **02.2 执行**：`executeToolCall` 只认"名字 + 参数"；sandbox 根锚在代码位置；结果只打印——模型看不到（没有回填）。
- **02.3 闸门**：五道判断（未知工具 → JSON → 对象 → schema → 路径）；"不执行"是结构保证；拒绝是结果（退出码 6），不是异常。
- **02.4 证据**：用例矩阵 `scripts/tool-checks.sh`（11 项，离线免费）；`call` 直调与真实调用分别标注；矩阵第一天就抓出误拒 bug。

## 概念线

模型请求（02.1）→ 执行在环境里发生（02.2）→ 执行之前必须过闸门（02.3）→ 闸门的判断要被用例固化，误放与误拒都算 bug（02.4）。**能执行什么和绝不执行什么，是同一份契约的两侧。**
