## 核心结论（可迁移）

- 判据只有一条：下一步做什么，是否必须依赖运行时才能拿到的证据。能提前写死 → 普通程序或固定工作流；写不死 → 需要模型现场判断（Agent）。
- 复杂 ≠ 需要 Agent。“300 个文件重排 import + 全量测试 + 生成报告”步骤多但可写死，仍是工作流。
- 边界在控制流归属：控制流写在代码里 = 工作流（哪怕内部调用一次模型）；由模型逐步决定 = Agent。
- 环境是唯一事实来源：模型说“修好了”不算，diff 与测试结果才算。
- 三层职责：模型“想”（判断、生成）；Harness“管”（组织上下文、把模型输出变成合法动作、循环与边界、状态）；环境“发生”（文件、git、shell、测试、网络）。
- Agent 不消除不确定性，只把每一步决定变成可执行、可观察、可中断的动作。
