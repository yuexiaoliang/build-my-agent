## 核心结论（可迁移）

- 适配层是线上格式与内部表示之间唯一的翻译关口：入站 `parseChatResponse`，出站 `toWireMessage`；规范化集中做，代价是改写与丢弃无声。
- 现状全容忍：`content:null→""`、缺 `id/name→""`、缺 `index→`数组位置；`finish_reason`、`reasoning_content`、多余 choices、未知字段全部静默丢弃；唯一结构拒绝要求 content 与 tool_calls **同时**为空（`src/model.ts:136`）。
- 回放只走解析路径：不执行、不回填，服务端校验触达不到——"回放能过"与"循环能跑"是两回事。
- 空 id 的真实回填后果**未测定**：请求先被服务端以"须回传 `reasoning_content`"为由 400，id 校验是否会发生无从观察；对照组（正常 id）同样 400，说明 id 不是两次结果的差异变量。
- 单变量控制要核全字段：实验脚本漏带 `tools`（真实循环都带），幸存假设因此多一个——实验设计的教训。

## 关键代码与入口

- `src/model.ts:123` `parseChatResponse` 主流程；`src/model.ts:174` `readToolCalls`（规范化集中点）；`src/model.ts:154` `toWireMessage`（出站，只发 content + tool_calls）
- `scripts/empty-id-roundtrip.ts`（空 id 回填）、`scripts/valid-id-roundtrip.ts`（单变量对照）——对照 `scripts/orphan-tool-message.ts`（03.1）

## 运行证据

- `node src/cli.ts replay fixtures/ch04/surgery-{content-null,no-id,extra-field}.json` → 三份全部退出码 0（**离线回放**；content-null 的"回答"一节消失，no-id 显示空 `id=`，extra-field 无声）
- `node scripts/empty-id-roundtrip.ts` → HTTP 400，措辞指向 `reasoning_content`（**真实运行**，`fixtures/ch04/empty-id-roundtrip.json`）
- `node scripts/valid-id-roundtrip.ts` → 同样 400 同措辞 → 空 id 非扳机（**真实运行**，`fixtures/ch04/valid-id-roundtrip.json`）

## 失败与反例

- 预测"三份手术两份跑通"→ 实测三份全过：低估解析层容忍度；落差定位到 `readToolCalls` 的填 `""`。
- 预测"空 id 回填 → 400"：实测虽 400，但对照组（正常 id）同 400 → 结果与 id 无关；空 id 的真实后果被服务端另一层校验掩盖，未测定。
- 对照实验预测"仍是 400"→ 命中：服务端这次声明并执行了 `reasoning_content` 回传要求，与 03 章六次不回传却 200 冲突 → 触发条件未归因，不猜测服务端内部。
