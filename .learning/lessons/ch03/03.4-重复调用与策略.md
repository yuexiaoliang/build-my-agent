## 核心结论（可迁移）

- 分级处理：同一签名**连续**第 1 次正常执行 / 第 2 次执行并加提示回填 / 第 3 次起不执行、记录说明、结束循环。
- "连续"按**相邻**定义（与上一次调用相邻）——`read → edit → read` 这类合法重读不会误伤（06 章有写工具后更关键）。
- 两块防线分工：提示防"模型没意识到自己在重复"（便宜、保留纠偏机会）；停止防"提示无效还在烧预算"（硬止损）。只提示挡不住卡死，只停止会误伤。
- 停止轮的"回填"**到不了模型**（没有下一轮请求）——它留在转录与输出里给人看；要让模型看到需要一次收尾请求（多一步预算）。
- 误伤是真实代价：本次诱导重复是用户明确要求的，Harness 分不清"用户要的重读"和"模型卡住"，第 3 次直接停止、任务未按用户要求完成。
- 循环三种收场：自然结束 / 步数耗尽 / 连续重复停止，全部有明确输出与原因。

## 失败与反例

- 提示被无视：模型在提示之后仍继续重复——因为它服从的是用户"读三次"的指令。提示不是强制，不应假定它一定改变行为。
- 停止误伤：收场动作是保守的，可能覆盖用户明确要求；报告必须让"为什么停"可见（09 章人工介入的动机）。

## 我的判断与反馈要点

- 学习者主动给出**分级设计**并说明理由（"多方面处理，而不是只从一个点下手"）——首次主动设计循环策略；被采纳，实现时细化了阈值（第 2 次提示 / 第 3 次停止）与"连续"定义；设计题③（失败表现）由真实运行回答：误伤用户指令。
