# 后续单元怎样从设计规格变成可开课材料

S2–S5 的逐单元目的、活动、验收和依赖在 [课程索引](catalog.json)。这是完整路线的设计规格，不是已经实现的功能或写好的全部教材。不要用模板空栏冒充备课完成。

## 每个单元的交付门槛

开课前，导师或维护者准备与本单元对应的**具体小任务、直接前置、完整示范、必要图片、可执行实验、练习用途与依据、提示/补救分支、验收反例和复访点**。把材料放入 course/units，更新 catalog 的 material/status，再通过课程检查。学习者只看当前必需部分，准备责任不能转化为整章阅读作业。

第一条未知依赖必须显式说明：依赖库/模型/执行环境尚未配置时，不虚构命令。若需要付费调用或高风险副作用，先确定额度、工作区、权限与停止条件。安全保护可由 lab 预备，教学机制仍要由 harness 实现并单独验收。

## 各阶段的前置补法与反例

**S2**：用同一条 JSON 消息说明文本/对象/类型/校验的区别；随后依次建立模型接口、只读工具、结果关联和循环。每新增一条控制决策都配有触发条件和反例，尤其是禁用工具、组合预算、重复 id、截断及未知停止原因。先做可注入的离线输入，再核对真实协议，不先猜供应商行为。

**S3**：进入写操作前准备无私人数据的隔离工作区。用“已修改文件但回执丢失”完整示范日志与现实不同，再让学习者选择核对点。取消需从 UI 一直追踪到实际等待和工具；外层强停不是内层能力。协议流式解析与浏览器事件流必须分清。

**S4**：从文本搜索和单 Agent 开始建立基线。用一个丢失约束的摘要反例，再学习压缩与回取；用相同任务比较计划/委派的收益与额外成本。实验先写要检验的假设与可改变变量，保留任务不用于调优。样本不足时只报告观察，不硬凑统计结论。

**S5**：先定义一个真实可验证的用户流程，利用前端优势完成可视化控制和完整体验，再准备部署与维护。迁移项目先比较替代方案，企业服务不设为必修身份。答辩同时检查设计、诊断与交付，AI 仍可编码但不能代替学习者先作完全部判断。

## 选修方向

深入多 Agent 调度、长期记忆治理、模型训练协同与研究复现；成熟开源项目维护；业务访谈与企业试点；技术培训设计。仅在已有主线能力和实际兴趣/机会支撑时展开，不提前成为高压任务清单。

## 不做的事

不自动生成几十篇无代码/实验支撑的讲义；不先把生产级框架全部堆好再让学习者通读；不把学习起点清零理解为重新学全部前端基础；不承诺学完能够稳定解决任意任务或保证职业回报。
