# S1.4 · 这个任务真的需要 Agent 吗

**本步用途：** 让技术储备变成选型能力，不把所有需求 Agent 化。前置是看过最小执行链。**目标：** 根据决策来源和任务条件比较规则、AI 辅助、固定工作流与 Agent。

## 先示范两个选择

需求 A：固定返回 testing 文档里已知的测试命令。文件与字段均已确定，直接查询规则就能解决。本课用 Agent 形状的流程是为了学习机制，不意味着实际交付时应该这样做。

需求 B：面对陌生仓库，需根据读到的资料选择下一份文件，发现矛盾后继续调查并形成有依据的结论。这时值得比较受限 Agent 与预定流程；仍要考虑数据、风险、预算和可核验性，不自动得出必须用 Agent。

关键是下一步行动如何被选择：规则预定还是在约束内交给模型。普通 if/else 也使用运行时证据，例如测试失败按固定规则重试两次，不因此变成模型驱动 Agent。这是本课程采用的架构区分，不是唯一行业定义。依据见 [维护来源](../sources.md)。

## 共同完成一个小改动

由学习者先说想让界面哪一处更不容易误读，AI 提出最小改法并编码。只改一条状态说明或一处数据展开展示，然后复跑对应场景。解释输入、改动、结果和仍不能证明的事情。

这是 S1 的小作品练习，不自动记为自己已经实现 Harness。第二阶段才在 harness/ 创建自己的核心机制，不能直接把 reference 改名当独立作品。

## 选型练习

**用途：** 判断是否值得增加自主决策。**条件：** 每次把 3 个固定字段映射成一种固定输出，输入可严格校验，业务不需要自然语言理解。**问题：** 你会优先选择规则、固定 AI 流程还是 Agent？结论和一条依据即可；允许先说明缺失条件。

<details><summary>练习后核对依据</summary>
给定条件下规则应作为优先基线；引入模型没有显示必要收益，反而增加需要验证的行为。新条件出现时可以改选，但要说明哪一个条件改变。不是按“越智能越高级”排序。
</details>

## 阶段出口与可选表达

参照 [能力验收](../assessment.md) 的 S1：能指出信息怎样传递、执行怎样受控、终态与完成怎样区分，并为简单任务选择不使用 Agent。需要提示就记录提示程度，不能只因跑过四课就标为熟练。

完成后可以选择按 [作品表达](../../portfolio/README.md) 整理“界面显示成功，为什么还不能相信任务完成”。只使用自己核验的实验，标注脚本合成与真实运行；不愿发内容也照常进入技术主线。

本课没有硬性文章数、日更、粉丝或企业咨询任务。目标是增加技术与职业选择，不再造一份高压工作。
