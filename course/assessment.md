# 能力与验收

终点：面对没有原样讲过的需求，能比较简单方案与 Agent，提出约束与验收，借助 AI 编码，诊断失败并交付可用的 AI 应用。以 Harness 深化技术，以作品和可选表达增加职业选择，不承诺职业结果。

## 四种证据分开

作品证据是代码版本、实际命令、运行轨迹与独立结果核验；学习证据是学习者实际判断、依据、帮助程度和适用范围；教学行为证据是导师实际处理反馈的过程；外部反馈是明确场景中的实际用户或读者反馈。

课程设计或材料已准备，不代表实现已完成；AI 编码或测试通过，不代表学习者掌握。completedUnits 只表示学习过程走过，不能解释为掌握百分比。

| 能力 | 有价值的证据 | 不足以证明 |
|---|---|---|
| 解释 | 沿输入定位字段、状态和执行，指出条件变化的影响 | 背定义、复述刚给的答案 |
| 设计 | 在 AI 展开完整方案前提出需求、约束与验证办法 | 赞同现成架构 |
| 诊断 | 给出可区分假设，选择观测，解释修复为何成立 | 随机改提示直到一次成功 |
| 迁移 | 新任务中复用机制并指出必须重判的边界 | 原案例换名字 |
| 交付 | 干净环境可用，失败反馈清楚，关键检查可复现 | 一段成功录像 |

允许 AI 编码、开卷、运行和请求帮助。support 分 demonstrated / prompted / independent，具体 observation 与 source 必须真实。看图复述和导师已给关键推导后的回答不算独立判断；题目歧义要先修正，不作负面能力证据。

## 阶段出口

S1：从本地空白起点完成一个小功能，解释页面、服务、模型与结果的连接，用一次失败检查校准判断。

S2：自己的工具/循环实现通过正常与边界测试；未启用工具不执行、畸形响应不静默成功、组合策略不突破已约定预算。不是用参考程序代跑。

S3：在受控副作用任务中说明授权、取消与恢复边界。外层强制终止或临时桩件不能冒充内部代码已经取消或恢复成功。

S4：固定任务与预算比较策略，报告样本、失败、用量/费用和不确定性。负结果可合格，不为展示收益修改验收标准。

S5：陌生需求中先设计验收，再交付 Web 产品与不同场景迁移；通过未知故障的诊断解释。可以合理选择不使用 Agent。

## 实施方式

具体测试、场景和评分器在对应本地小步建立，并先用已知正反例核验。验收入口必须运行当前作品，不能由预制参考实现代替；正式保留用例与被测代码的访问/修改权限分开，目录名本身不是隔离保证。

每步新增行为配当前必要的检查，允许先有测试再逐步实现；不为“测试齐全”提前搭建所有后续功能。开始正式验收前说明目标、可用帮助与范围。检查不足就记录限制，不宣称覆盖任意任务。

当前骨架没有程序、预制题库或成绩。真实学习时才积累证据；卡住补具体连接，不重置全阶段，也不无限考试。安全相关误解先澄清再允许相应动作。

主线成果是自己的 Harness、完整 Web 作品、一个对照实验和一次独立迁移说明。公开文章、粉丝、收入、咨询成交均不作为技术学习的硬门槛。
