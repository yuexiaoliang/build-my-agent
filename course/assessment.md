# 能力与验收：作品运行，判断有据

终点：面对没有原样讲过的需求，能比较简单方案与 Agent，提出约束与验收，借助 AI 编码，诊断失败，说明证据与边界，交付可用的 AI 应用。以 Harness 为技术深入点，保留前端优势，不承诺职业结果。

## 四种证据分别记录

**作品证据**：代码版本、命令、轨迹和独立结果检查。**学习证据**：学习者实际作出的判断、依据、支持程度和范围。**教学行为证据**：导师在合成或实际多轮对话中怎样处理卡点。**外部反馈**：真实用户或读者在明确场景下的反馈。

一种证据不能替另一种作保。实验台 reference 已实现也不能算学习者作品。completedUnits 表示学习过程走过，不是掌握百分比。

## 判断任务

| 能力 | 合格的证据 | 不足以证明 |
|---|---|---|
| 解释 | 沿一个输入定位消息、字段、执行与结果；指出一个条件变化的影响 | 背定义或复述刚展示答案 |
| 设计 | 在 AI 给完整方案前提出需求、约束、选项和验证办法 | AI 给方案后表示赞同 |
| 诊断 | 提出可区分假设，选择观测，解释为什么修复成立 | 反复改提示词直到一次通过 |
| 迁移 | 在不同问题中复用机制，说明哪些边界必须重做 | 原案例换几个名字 |
| 交付 | 干净环境可启动，操作和失败反馈清楚，能重跑关键检查 | 只展示一段成功录像 |

允许 AI 编码、开卷、运行和使用文档。帮助分别记 demonstrated / prompted / independent。独立判断任务只评价实际观察范围；提前给完整故障原因后不能再计独立诊断。题目无效先修题，不将歧义计入能力缺口。

## 阶段出口

S1：说清界面、请求、工具、来源检查的区别；能比较固定任务为何可不用 Agent。
S2：自己的实现通过未启用工具、截断、预算/重复组合反例；能解释而非只运行参考代码。
S3：在受控副作用任务中解释授权、取消和恢复；外层实验台强制终止不能冒充内部取消正确。
S4：固定任务与预算做对照，报告重复次数、费用/用量与不确定性；负结果可合格。
S5：陌生需求中先设计验收，再交付 Web 产品和一个不同场景迁移；用一个未知故障作技术答辩。

正式验收前公开目标、允许帮助与评价范围，保留具体用例避免先调优。检查器放在被测工作区之外；用已知正反样例校验检查器。不可让 Agent 修改隐藏任务后自称通过。

## 复访与补救

下一次使用或隔课恢复时，用一个小变化复访关键连接。失败就补具体前置/示范，不全章重考；用户要求继续可保留待复核项。安全相关误解先说明保守边界，不能带着误解开放高风险动作。

主线毕业需要自己的 Harness、完整 Web 作品、一次对照实验和一次独立迁移说明。公开文章可选；粉丝、收入和咨询成交不是学习验收。企业服务、深入多 Agent 和研究方向在主线之后按真实需求选择。
