# AI 应用工程能力与验收

目标是面对没有原样讲过的需求，能借助文档和 AI 编码，独立定义问题、选择方案、解释证据、诊断失败并交付可维护的应用。Harness 是入口和重点纵深，课程同时验收 RAG、AI UX、多模态/Realtime、评测、可观测性、后端、安全和模型优化。

## 四种证据分开

作品证据包括代码版本、实际运行、轨迹和独立结果核验；学习证据包括学习者作出的判断、依据、帮助程度和适用范围；教学行为证据记录导师怎样调整帮助；外部反馈来自明确场景中的实际用户。

材料 prepared、功能实现、测试通过、学习者掌握分别判断。允许开卷、查文档和让 AI 写代码，关键选择与证据解释逐渐由学习者承担。

## 快速通过与能力证明

学习者表示熟悉的知识默认略过基础讲解，可复用已有作品与当前任务中的判断，无需逐项考试。跳过属于教学安排，不自动增加 completedUnits 或 independent 证据。历史证据不足或仅为 prompted，不要求重学；遇到具体缺口才补局部。

独立证据来自未预先给出结论的产物或新条件中的判断，不能从照读示范推定。没有独立证据也可以继续学习；综合验收时核对必要证据，不把每一步变成关卡。

## 从入口开始的最低证据

入口本身只需一个小任务、可观察成功条件、必要运行记录和一个值得解释的变化。核对模型提议、程序权限/参数检查、真实工具结果、结果关联与停止边界；模型说已完成不等于外部结果正确。

真实模型的工具选择和回答能力必须以经授权的实际调用验证。合成事件只证明本地执行、关联和停止等机制。缺少模型条件时明确保留未验证范围，可以继续独立本地机制；不得据此宣布模型能力已验收。

随后按实际出现的能力增加证据：检索出现时分别看召回和回答，动作有副作用时检查权限、幂等和结果不确定性，媒体出现时核对真实链路。系统评分器、统计比较和 trace 聚合逐步深入，不要求第一步搭完整平台。

## 核心能力

| 能力 | 可用证据 | 不足以单独证明 |
|---|---|---|
| 解释 | 沿实际输入和轨迹定位模型、检索、工具、状态或媒体之间的关系 | 复述术语或计划图 |
| 设计 | 完整方案出现前提出需求、约束、选项和验收，允许选择简单方案 | 接受导师给定架构 |
| 实现与验证 | 能指导 AI 作有范围的修改，核对关键入口、失败和最终结果 | AI 完成代码或测试变绿 |
| 诊断 | 提出可区分假设，选择证据并验证修复 | 随机换 prompt 到一次成功 |
| 评测 | 成功条件、任务集、评分器校验、保留样例和失败记录 | 少数成功样例 |
| 优化 | 固定任务与版本，比较质量、延迟、成本和复杂度 | 单独的 token 下降或一次更快 |
| 安全 | 程序边界实施身份、数据和工具权限，并有反例 | 提示词要求模型不要越权 |
| 迁移 | 改变需求、数据或约束后重新选方案，并解释未验证边界 | 原项目换名字 |
| 交付 | 干净环境启动、受控使用、故障定位和可复现回退 | 只有成功录像 |

## 自然复访与帮助递减

初次可完整示范，再次使用时由学习者选变量或提出诊断，知识组应用时由学习者先定约束与验证。按实际表现调整帮助，不按课次强制撤掉。

在一个知识组的实际应用中改变一项关键条件，形成近迁移；后续任务自然复用已有机制，最后再做陌生场景综合迁移。已有足够证据的能力可直接使用，不重复安排同样检查。一次失败只定位局部缺口。

知识组出口以 catalog 的 groups.exit 与具体单元 acceptance 为准；分组不是固定阶段，验收不要求按编号走完目录。

## 毕业证据包

可来自一个主产品和少量有明确目的的专项实验，单个产品无需装入全部技术。至少保留：

1. 一个真实模型参与、具备前后端和可用交互的 AI Web 产品，并说明模型相对简单基线的价值及局限。
2. 一条有 retrieval/answer eval 的检索或 RAG 链路，核对引用、权限以及资料更新/删除后的行为。
3. 一个逐步构建的 Harness：工具契约、动态循环、任务状态、预算/停止与一种生态集成；能独立诊断一个执行或恢复故障，结果通过环境核验。规划与委派有收益比较或不采用的依据。
4. 一次真实图像/文档实践与一次 Realtime/低延迟音频交互，能诊断媒体、会话和界面状态。
5. 一套可重复 eval、回归和 trace/metrics 证据，模型、提示、数据与配置版本可识别；评分器先由正反例校验，权限类要求不依赖模型评分器作唯一裁判。
6. 一次模型或系统优化比较，报告质量、延迟、费用、复杂度和未验证范围；负结果和回退可以是有效成果。
7. 一次实际部署，验证当前产品需要的配置、secret、授权、隔离、配额、后台任务和监控，以及一次降级或回退。
8. 一次受控试用或任务观察，由使用证据提出并验证改进；自己试用与真实用户反馈分别标注，未获得外部反馈时保留缺口，不虚构使用者。
9. 一个陌生需求中的架构选择与关键实现，在 AI 展开完整方案前由学习者提出约束、验证和迁移边界。

## 技术边界

系统覆盖主要 AI 应用技术面。fine-tuning、蒸馏和合成数据需要掌握适用问题、数据条件、评测与回滚，训练实验按实际条件选做。预训练、CUDA、分布式训练和推理内核不作为毕业前置。
