# 从 Harness 整体进入，沿实际问题拆解

总目标是独立完成 AI 应用工程工作，允许查文档、使用框架和让 AI 编码。学习者逐渐负责定义问题、选择方案、解释证据和判断是否交付。Harness 提供整体入口和重点纵深，技术覆盖见 [技术地图](technology-map.md)。

## 一个有边界的整体入口

新入口由 [catalog.json](catalog.json) 的 `entryUnit` 指定：围绕一个小任务，观察“用户目标 → 模型提出动作 → 程序校验并执行只读工具 → 返回 observation → 下一次判断或结束”。从第一次实验就有成功条件、必要日志和明确停止原因。

入口只构建当前任务需要的最小运行，不预制后续 RAG、记忆、规划、委派、持久化和恢复系统。首次示范把必要机制交代清楚；更深原理留给实际问题。若暂缺真实模型条件，可验证程序边界并明确标记合成输入，模型工具选择与回答能力保持待验证。

已有代码可按当前任务需要复用；已删除单元不参与选课。历史证据保留原编号和支持程度，不要求恢复旧讲义。衔接规则在 catalog 的 `navigation.resume`；用户授权的导航迁移只调整续学位置，不代表发生了授课或能力验收。

## 第一性原理怎样落实

从任务目标和可观察约束出发：信息是否足够，输出是否满足契约，动作由谁授权，状态在哪里，怎样判断成功，时间和费用预算是多少。针对未知环节提出可区分的解释，再改变一个条件观察结果。

每次拆解停在足以支持当前设计或诊断判断的位置。具体模型行为需要实验；不要求先推导模型训练、Transformer 或所有后端基础。简单规则和固定 Workflow 保留为方案选择的基线，增加复杂度应有可验证收益。

## 由现象选择知识路径

| 当前需要解释的现象 | 进入的知识组 | 本步优先形成的判断 |
|---|---|---|
| 工具请求怎样变成动作 | 工具契约、Workflow、Harness | 模型提议和程序执行的边界 |
| 结果遗漏信息或结构不符合要求 | 模型基础、上下文、输出契约 | 上下文、结构约束与语义质量各自影响什么 |
| 循环重复、状态混乱、任务不结束 | 循环、状态、预算、记忆 | 哪个机制解释现象，如何控制和验证 |
| 缺资料、检索无关、引用失真或内容过时 | RAG 与数据生命周期 | 召回、回答依据、权限和更新是否分别正确 |
| 超时、重复副作用、取消后仍在执行 | 可靠执行、安全、必要后端 | 能否重试，动作是否已发生，怎样恢复 |
| 看不懂图片或语音交互不顺畅 | 多模态与 Realtime | 媒体、会话和界面哪一环节造成问题 |
| 更慢、更贵或改动后效果变差 | Evals、Observability、优化 | 用相同任务与版本证据比较方案 |
| 别人无法使用或上线后出现退化 | 产品交付、试用与运维 | 用户结果、诊断、降级和回退是否可用 |

具体候选路径只在 catalog 的 `routes` 维护；路径可以交叉，同一单元不重复教学。groups 是知识分组，`requires` 只表达直接知识依赖。已有经验可满足依赖，只有实际缺口才回溯，不把依赖图变成新的通关清单。

## 熟悉内容怎样快速通过

学习者表示熟悉的内容默认略过基础讲解，已有作品和自然发生的判断帮助定位。跳过无需逐项考试，也不自动记为独立掌握。需要使用时先复用，遇到具体问题再补局部。

例如，会 Adapter 就直接复用 Provider 边界，重点观察模型能力差异；会状态管理就关注远端执行与界面状态是否一致；会类型和校验就重点区分结构正确与任务正确。历史记录仅有提示下回答，不能据此判定需要重学。

## 逐渐接手判断

首次接触可由导师完整示范，学习者选择一个条件观察变化；再次使用时由学习者提出方案或诊断假设；阶段应用时先由学习者确定约束和验证办法，再使用 AI 实现。帮助随实际表现调整，不按固定课次强制撤掉。

复访利用后续任务自然发生，不以连续问答或每步测验凑证据。一个主产品搭配少量专项实验，RAG、多模态、Realtime 等可以有独立任务，单个产品不必承载全部技术。

## 从入口积累证据，按需深化

最小任务集和观察记录从入口开始；检索出现时检查检索与回答质量，工具出现时检查真实结果和执行权限，副作用出现时检查重试与恢复。完整 grader、trace 聚合、统计比较、优化和生产运维在需要时深入。

尚未备课的单元保持 `planned`、`material=null`。它们只是设计，不代表实现、试教或掌握。只为当前小步生成材料。[能力验收](assessment.md)规定证据，个人结果只记入 `.learning/state.json`。
