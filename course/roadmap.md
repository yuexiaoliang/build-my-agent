# 课程路线

本页由 course/catalog.json 生成，使用 `node scripts/check-course.mjs --write` 更新；不在本页手工维护当前进度。ready 表示可开始教学，不表示学习者已掌握；planned 是后续单元规格。

## S1 · 做通一个可观察的 AI 功能

阶段出口：分清界面、服务端、模型与依据；完成一个小变化并解释。

### S1.1 回答从哪里来 · ready

目的：看到一条完整数据链，不先背术语。

活动：在 normal 场景沿 testing 结果追踪到下一轮 messages。

验收：能指出模型请求、实际执行与来源检查分别发生在哪里。

[当前材料](units/S1.1.md)。直接前置：无；利用已有前端经验。

### S1.2 界面开关不是执行边界 · ready

目的：把前端交互连接到服务端的实际决定。

活动：关闭工具后运行；再用最后一轮预算观察没有执行。

验收：能说明前端表示意图，服务端仍必须实施限制；不把演示开关当企业授权。

[当前材料](units/S1.2.md)。直接前置：S1.1。

### S1.3 结束了，还是完成了 · ready

目的：用失败与取消理解状态不是一个布尔值。

活动：比较 unsupported、truncated、slow；观察取消确认。

验收：能区分 answered、matched、cancelled 与自己的理解证据。

[当前材料](units/S1.3.md)。直接前置：S1.2。

### S1.4 这个任务真的需要 Agent 吗 · ready

目的：不为技术兴趣给简单需求增加复杂度。

活动：比较已知 testing 查询的规则方案与动态调查方案，做一处可解释小改动。

验收：能解释为何固定查询可以不用 Agent，保留证据与失败边界。

[当前材料](units/S1.4.md)。直接前置：S1.3。

## S2 · 构建自己的最小 Harness

阶段出口：自己的实现通过正常链与边界反例，而不是只运行参考代码。

### S2.1 从一条输入输出契约开始 · planned

目的：让类型、实际数据和错误边界对应。

活动：在 harness/ 创建自己的消息与响应契约，用有效/畸形输入测试。

验收：无效输入显式失败，类型声明不能冒充运行时校验。

[当前材料](future-units.md)。直接前置：S1.4。

### S2.2 工具请求怎样成为合法动作 · planned

目的：分离提议、校验、启用范围和执行。

活动：自建只读工具集合；给未知工具、坏参数、无权限请求。

验收：未许可动作不执行，拒绝有依据，工具结果关联回正确请求。

[当前材料](future-units.md)。直接前置：S2.1。

### S2.3 循环、预算与停止 · planned

目的：组合策略仍须遵守执行契约。

活动：自建最小循环；用最后一轮+三重复请求的组合反例验证。

验收：轮数与工具预算分别受控，已执行/未执行报告真实。

[当前材料](future-units.md)。直接前置：S2.2。

### S2.4 可复现的结果与协议对照 · planned

目的：让运行和检查可以独立复核。

活动：记录独立 run id、消息、终态；比较一个实际可用接口或已注明的合成协议。

验收：旧证据不可覆盖；解析回放与完整循环测试分别说明。

[当前材料](future-units.md)。直接前置：S2.3。

## S3 · 让执行可控可信

阶段出口：能够约束有副作用任务，解释真实状态和恢复边界。

### S3.1 授权与受控编辑 · planned

目的：允许某个动作，不等于允许之后所有动作。

活动：预置独立工作区，审批绑定具体参数和内容版本，再实现受限补丁。

验收：参数变化需重新决定；路径、符号链接与执行隔离不混淆。

[当前材料](future-units.md)。直接前置：S2.4。

### S3.2 流式与取消传播 · planned

目的：前端停止显示不等于后台停止工作。

活动：在自己的实现接入增量响应、输出限制和取消；加入慢消费者与超时场景。

验收：取消后无新动作，无法终止者标状态未知；不能伪称回滚。

[当前材料](future-units.md)。直接前置：S3.1。

### S3.3 记录与恢复 · planned

目的：日志里的成功与环境里的结果可能不同。

活动：模拟动作成功但确认丢失，核对环境再决定恢复或人工处理。

验收：不盲目重试副作用，记录幂等边界与无法确定的状态。

[当前材料](future-units.md)。直接前置：S3.2。

### S3.4 独立结果核验 · planned

目的：测试通过不是需求完成的全部证据。

活动：在隔离环境修复小缺陷，核对补丁范围、测试、工作区和需求。

验收：拒绝修改评分器冒充成功，说明哪些检查不能覆盖。

[当前材料](future-units.md)。直接前置：S3.3。

## S4 · 处理复杂任务并做实验

阶段出口：用证据解释上下文、规划和模型/系统取舍。

### S4.1 检索与上下文选择 · planned

目的：把必要资料提供给模型，而不是一次塞整个仓库。

活动：先做文本搜索基线，再选择片段并记录来源/截断边界。

验收：信息缺失时补检索或承认限制；不把外部文本当授权指令。

[当前材料](future-units.md)。直接前置：S3.4。

### S4.2 压缩、任务状态与记忆 · planned

目的：省下的上下文可能包含关键约束。

活动：比较原文、摘要和回取；区分当前任务状态与跨任务记忆。

验收：测试约束丢失、过期和污染，缓存指标只报实际可观察值。

[当前材料](future-units.md)。直接前置：S4.1。

### S4.3 规划、委派与扩展 · planned

目的：复杂性增加之前先证明需要。

活动：同一任务比较简单循环、固定流程和有限委派；按需接入 MCP。

验收：解释输入输出、预算与取消边界；多 Agent 无收益也可合格。

[当前材料](future-units.md)。直接前置：S4.2。

### S4.4 评测、消融与性能 · planned

目的：一次看起来更好不构成收益证据。

活动：固定任务和预算，重复比较一个策略；校验评分器与保留任务。

验收：报告样本、失败、费用或用量和不确定性；不伪造显著提升。

[当前材料](future-units.md)。直接前置：S4.3。

## S5 · 交付 Web 作品与独立迁移

阶段出口：在陌生需求中主导判断，完成可运行与可解释的作品。

### S5.1 把控制能力做进界面 · planned

目的：让使用者理解正在发生什么和可以控制什么。

活动：为自己的 Harness 做运行轨迹、审批、停止、结果审阅和故障反馈。

验收：端到端验证，界面不把请求取消或网络断开当后台确认。

[当前材料](future-units.md)。直接前置：S4.4。

### S5.2 配置、部署与维护 · planned

目的：别人能启动、定位和安全使用，才算可交付。

活动：准备配置诊断、发布与回归；实际选一种部署环境。

验收：密钥留服务端；多用户先补认证、配额和隔离；未验证平台写清。

[当前材料](future-units.md)。直接前置：S5.1。

### S5.3 迁移到一个新需求 · planned

目的：把可复用机制与领域约束分开。

活动：先调研具体流程，再比较规则/AI 辅助/工作流/Agent，选择一项迁移。

验收：允许不用 Agent；给出约束、最小验证和退出条件，不冒充行业专家。

[当前材料](future-units.md)。直接前置：S5.2。

### S5.4 技术答辩与作品表达 · planned

目的：把真实能力沉淀成可以核验的证据。

活动：未知故障诊断+独立设计评审；可选整理一份公开案例。

验收：本人能解释关键判断；保留失败与限制，不以粉丝、收入或写文章数量验收。

[当前材料](future-units.md)。直接前置：S5.3。

研究、深入多 Agent、行业咨询和企业培训为后续选修，不作为当前主线身份与毕业门槛。个人品牌从真实作品中选择性沉淀，不设置日更或收入目标。
