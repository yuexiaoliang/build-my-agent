# 课程路线：规划先行，实现随学习发生

目标是深化 AI 应用工程能力，Harness 是技术深入方向。学习从本地第一个问题与第一个小功能开始，不先阅读预制系统。

## 五阶段

| 阶段 | 作品怎样成长 | 判断能力 |
|---|---|---|
| S1 做通一个可观察的 AI 功能 | 从需求、最小调用到页面与服务连接，再处理一个失败 | 解释输入输出和边界，比较是否需要 Agent |
| S2 构建自己的最小 Harness | 在 S1 作品上逐步加入契约、工具、回填、循环与控制 | 区分模型提议与程序执行，测试关键约束 |
| S3 让执行可控可信 | 到需要时再加入授权、隔离、取消、记录、恢复与核验 | 判断实际状态、失败后果与副作用边界 |
| S4 处理复杂任务并做实验 | 按需增加检索、上下文、记忆、规划和有限委派 | 建立简单基线，验证改动收益与代价 |
| S5 交付 Web 作品与独立迁移 | 在自己的作品上完善体验、部署与维护，处理新需求 | 独立提出约束和验收，解释迁移与不采用 Agent 的取舍 |

单元级目的、活动、验收与直接前置只在 [catalog.json](catalog.json) 维护，不在本页再复制一份。依赖是建议的学习路径，不是固定课时或考试门槛；依据实际理解补最小前置，改路线时说明原因并同步索引。

## 备课与状态

骨架中全部单元为 planned，material 为 null，表示只有设计规格。具体讲义、图片、代码和测试由本地导师在即将开始的当前小步按需准备/增量实现，使用 [备课模板](templates/lesson.md)。不先生成整章或完整参考项目。

planned → prepared：当前小步可讲的示范、必要图文、练习依据和补救方式已准备，material 指向实际存在文件。实验未运行仍写计划；不能为了 prepared 预先完成本步全部实现。实际授课后可记 taught。材料状态、代码实现、测试结果和个人理解分别记录。

material 为 null 不要求读一个通用成品教程，也不阻止开始学习；它触发当前小步备课。跨会话只恢复 `.learning/state.json` 指向的必要内容，不因为状态空白反复问已知开发经验。

## 深度与作品

核心机制需要借助 AI 亲历设计、实现与验证；外围工具按需要选型，不把手写依赖或框架数量当能力。配图在需要时实际生成，没有原生出图能力也不默认取消图片。

[能力验收](assessment.md)关注解释、设计、诊断、迁移与交付。经过验证的实践可按 [portfolio](../portfolio/README.md) 整理为作品说明或专业表达，但不替代技术学习和验收。
