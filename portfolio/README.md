# 从作品到专业表达

经过验证的实践可以进一步整理成作品说明、技术文章、演示或其他专业表达。表达建立在真实技术积累上，不反过来决定课程内容，也不替代工程验收。

每个值得整理的案例，尽量保留一份事实原稿：

**问题与受众：** 谁遇到什么困难？为什么这个问题值得讲？

**选择与实现：** 为什么用规则、单次模型、工作流或 Agent？核心代码和版本在哪里？

**证据：** 场景、输入、运行命令、输出、独立核验与失败。合成、真实调用和实际用户反馈分别标明。

**边界：** 哪些没有验证？个人实验、合成案例和真实部署不能互相冒充。

**一项可带走的判断：** 读者在类似问题中可以先检查什么？

同一份事实原稿可以根据受众调整表达，但不能为了传播效果改变实验结论、隐藏关键失败或夸大适用范围。准备作品集时，优先保留可运行演示、关键取舍、失败复盘和已知限制。

公开内容不得包含未授权的工作资料、敏感业务数据、密钥或他人私人信息。需要使用外部素材、截图或真实案例时，先确认是否有权公开。
