# 教学配图：先确定要看懂什么，再选择怎么画

交付目标是**图片＋读图说明＋可追溯来源**，不是绘图代码、素材清单或另一套阅读作业。Mermaid 是标准关系图的一种实现，不是配图能力的上限。本 Skill 是操作规范，不会凭空增加模型或客户端的工具能力；宿主规则、可用工具和用户授权优先。

## 1. 触发与分工

当导师正在备课/解释，且图能帮助理解角色、顺序、状态、字段对应、定量变化或实际画面时使用；用户明确要求教学配图或改图时也使用。短定义、普通问答、仅修链接或仅讨论选型时不强行画图，更不一次生成整章素材。

`agent-harness-tutor` 决定学习目标、前置、展示时机与练习；本 Skill 负责视觉方案、制作、校验和交付，然后交还给导师带读。按需读取本文件即可协作，不要求用户再调用另一个角色，也不要求独立子 Agent 服务。制作失败不触发课程通关，不修改个人掌握状态。

## 2. 从已有上下文提取一个小任务

复用当前讲义、代码、数据和对话，在工作记录中确定以下信息，不让学习者填写表格：

- **目标与卡点**：看完应分清哪一个关系/变化？已经教过什么？
- **事实与版本**：当前代码位置/提交、数据来源或实际截图；标明实测、静态概括、合成示意或计划。
- **范围与展示时机**：本次只看什么、暂时省略什么；是带答案的示范，还是必须避免泄题的练习图？
- **交付条件**：客户端一定能显示图片；默认交付 PNG，不要求内联 Mermaid。只核对实际可用的制作工具和图片引用方式，不重复询问显示能力。

缺少截图目标时先定位实际文件或请求提供目标；不能凭文件名想象图像内容。缺少实验数据时不得画出“实测结果”。其余非关键外观可选合理默认值；不因为配色、宽度等中断授课。

## 3. 按学习任务选路径，不按工具反推课程

| 要看清什么 | 默认候选路径 | 改用其他路径的信号 |
|---|---|---|
| 职责、流程、调用时序、状态转换 | Mermaid → 渲染图片 | 需要精确字段对齐、复杂排版，或图拥挤到妨碍带读 |
| JSON/代码/内部对象逐字段对应，局部放大，上下文内容块与前后对照 | SVG 或 HTML/CSS → 渲染图片 | 需要观测真实界面时改用真实截图，不能用重绘代替 |
| 成功率、耗时、成本、分布或误差范围 | 数据 → 合适的绘图库（如 Matplotlib）→ 图片 | 简单已有图可复用；不把可量化关系交给自由生成图片 |
| 浏览器、终端、运行界面中的实际细节 | 真实截图 → 保留原图 → 裁剪/标注副本 | 没有实际画面就是证据缺口，不能生成一张冒充 |
| 确实有助理解的类比、场景、概念插画 | 宿主允许且实际可用的图像生成工具，或合适的现有素材 | 精确机制/数据仍由图源和数据表达；没有生图工具不影响其他路径 |

这是默认选型，不是硬性的工具排他规则。先用能清楚表达的最简单方式；不让 Mermaid 承担不合适的版式，也不为了炫技引入新框架。制作具体图时按需读取 [制作路径](references/rendering.md) 的对应小节，不整份加载所有工具资料。

## 4. 让一张图承担一个明确解释

沿用讲义的文件名、调用 ID、变量与步骤编号。先画一条正常路径；需要对照时保持输入和命名一致，只突出改变的条件。可以拆成少量逐步图片，不强制动画，也不把整套未来架构塞进第一张图。

文字、节点和箭头必须能对应代码或事实；箭头应说明是传递、依赖、返回还是状态转换。实际比例、数值和坐标要有依据；非比例示意标明“不按比例”。普通文本中的未知条件不能在图里悄悄变成已知。

中文标签简短可读，图注说明从哪里开始看。使用标题、线型、编号等区分，不仅靠颜色；按正常聊天显示宽度检查，不通过缩成小字容纳更多内容。图片不能只是给长段文字加方框。

先区分示范与练习：答案、错误标记、强调样式、图注、替代文字和文件名都不能在练习阶段泄露保留答案。已展示关键判断的图属于有支持的练习，不是独立迁移证据。

## 5. 实际制作、复用与交付

**文本模型 → 图源/代码 → 工具生成图片 → 客户端显示。** 不要求原生图片输出；图像输入能力、工具执行能力与图片生成能力也不互相推断。宿主要求使用某个图像工具时遵从，不能用本 Skill 越过宿主约束。

备课优先生成关键图片。复用前核对源文件、代码/数据版本及适用条件；图源或数据变更后重新生成，不能拿旧图证明新行为。无执行工具时使用匹配版本的已有图片；没有产物则明确缺资源，临时讲解可以继续，但配图仍是未交付。

保留一份权威图源：Mermaid 可继续保存在讲义块中，其他源文件放在对应课程资源目录；不要手工维护两份相同图源。课程新增持久资源可按 `docs/lessons/chNN/assets/<小步>-<用途>.<扩展名>` 命名（路径约定，不是已存在文件）。每张图在原讲义记录来源版本、制作命令/工具版本、图片位置与检查状态，不另造全局资源管理系统。

不同讲义使用独立输出目录，避免同名覆盖。`.lesson-preview/` 是临时预览，不等于已发布资源。提交图片沿用仓库授权与相关文件范围；未授权不新增外部托管或在线渲染上传。截图和课程记录中的密钥、令牌、个人信息必须先处理，不能把脱敏只做在文字里。

## 6. 检查完成后再说完成

依次检查下列层次，分别报告，不将其中一种替代另一种：

1. **内容**：机制/数据是否忠实，图文条件与代码一致，示意/计划/实测标注正确，练习未泄题。
2. **产物**：制作命令实际执行，文件存在且能解码，尺寸/格式正确，图片与当前图源对应。
3. **视觉**：实际查看图片中的中文、裁切、遮挡、连线与阅读顺序；能看图就检查并修正。无法看图时注明视觉检查未做，不能以渲染退出码代替。
4. **交付**：用当前客户端支持的图片附件或图片引用实际嵌入；核对地址/附件确实对应产物，不把本地路径或 GitHub 文件浏览页伪装成图片地址。

持续渲染失败时先定位错误、尝试合适的已有替代路径；不要无限重试、擅自安装依赖或索取学生配置工具。真实界面观测缺失、没有新图工具、图片过期都报告具体缺口，不改写为“客户端不能显示图片”。

## 7. 把结果交还课堂

对学习者只呈现当前必要图片和短带读：**看图目的 → 阅读入口 → 关键变化 → 对应代码/证据**。不展示内部选型清单和完整制作日志；输出方式遵从宿主图像工具的交付要求。

供导师/维护者恢复的最小记录放在现有讲义的验证记录中：

```text
用途与证据类型：
源文件/数据/截图及版本：
实际制作方式与图片位置：
内容 / 产物 / 视觉 / 交付检查：分别填写已做或未做及依据
读图入口、必要的图注/替代说明：
仍缺什么：无，或具体限制（不得虚填“全部通过”）
```

没有图片时返回“未生成/未交付＋原因＋可做的部分”，不要假链接；课程掌握状态由导师根据真实学习证据判断。制作 Skill、渲染一张图、课上看懂、隔课能迁移是四件不同的事。

维护或验收本 Skill 时读取 [回归案例](references/review-cases.md)；这些是待执行的检查规格，不是已经验证所有模型/环境的声明。
