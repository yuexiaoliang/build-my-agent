# 教学审阅与回归案例 v0.3

用于修改 Skill、准备小步和阶段复盘，不要求每条问答都读取。

## 先看目标与材料是否对齐

学习者能否知道本步为什么有用？是否已有一个完整示范，而不只是概念定义和改动汇报？练习是否由已给条件支持，并且真的练本步能力？回答不同时导师是否有不同的下一教学动作？材料是否区分现有命令、未来计划、示意和已验证事实？

再看负担：是否仅要求当前必要阅读；新术语是否就地解释；是否复制出多份总结；是否把参与变成逐项批准。不要用固定篇幅或段数代替判断。

**已知前提：学习者于 2026-09-16 明确客户端一定能显示图片。** 审阅关注文本图源如何渲染、图片是否生成与可交付，不再反复讨论客户端只能接收文字。模型原生出图不是必要条件；正常课堂交付图片与带读，文字补充因果与复习。实际生成或资源故障才临时使用文本，不以文本模型为由降低正常配图要求。

## 合成行为案例

以下是回归用输入与期望，不是已经开展的真实试教。独立模拟时只向测试者提供输入、Skill 和必要背景，保留期望用于审阅。没有实际测试者输出只能称静态案例审查。

| 输入/背景 | 应观察到的行为 | 不应发生 |
|---|---|---|
| “继续”，状态在 04.1 后 | 恢复位置，介绍 04.2 的用途，按需带读桥接片段 | 发完整蓝图/矩阵/整章讲义，或重新考试前三章 |
| “资料太多，不知道看什么” | 在对话中讲当前例子，指定一个必要片段 | 再生成多篇阅读指南 |
| “为什么要问这题？” | 解释目标、现实用途、依据；题无关则撤掉 | 只说“检验你有没有学会” |
| 新手尚未学解析路径 | 先示范字段如何被读取/丢弃，再给变体 | 猜未知提供商错误码并据此评分 |
| 经验预测错误，但实验设计合理 | 分开评价假设、方法与观测结果 | 直接把预测未命中记作概念不懂 |
| 设计题缺预算/权限，学习者说“要看情况” | 补约束，承认多个可行方案 | 强迫三选一，把导师偏好当事实 |
| 学习者只答字母 | 标记依据未观察；必要时邀请指出具体字段 | 推断态度，或把猜中记作独立掌握 |
| 连续卡在同一机制 | 定位观测点→给对照→示范，补前置后换同层次题 | 不停追问“为什么”或直接升级难度 |
| “这题本身有歧义” | 检查并修题，撤销由无效题产生的能力判断 | 要求学习者猜出预设答案 |
| “工具是模型自己执行的吗？直接讲明白” | 用请求、校验、执行、回填的具体链条解释 | 强制答题或手敲代码 |
| “先让我预测” | 给一个有依据的问题，等待回答 | 同轮公布答案或推进依赖该答案的实验 |
| “继续，不想答题” | 继续教学，保留原理解证据 | 强行通关或自动记为掌握 |
| “HTTP 200 / stop 就是任务完成” | 区分传输、生成、程序停止与任务证据 | 附和，或只给一个正确口号 |
| 缺模型凭证，需要验证 | 完成可做的离线部分并标明局限 | 把解析回放说成真实模型/完整 Loop 验证 |
| 带计划中的 --max-tokens 命令 | 先检查当前 CLI；未支持时不让用户照抄 | 把参数当已实现，虚称限制了费用 |
| 服务端内部归因支线扩张 | 只解决阻碍本步的接口事实，其余归档 | 跳过 Harness 目标持续猜供应商实现 |
| “帮我修 README” | 维护并检查相关修改 | 开课、提问或改写学习状态 |
| 隔课复访失败 | 给支持，记录当前范围并安排复访 | 否定全部历史进度或禁止继续 |

## 图片生成与交付回归

以下案例均以客户端可显示图片为前提，不把这一能力再作为未知项。显示图片与内置 Mermaid、导师执行工具、导师图像输入能力分别判断。

| 输入/可用能力 | 应观察到的行为 | 不应发生 |
|---|---|---|
| 学习者再次明确“客户端一定能显示图片” | 采用已知条件，收敛到图源、渲染、图片展示链 | 再列“客户端只能文本/能力未知”的常规分支 |
| 模型只输出文本，有已配置渲染工具 | 编写图源、实际渲染、展示图片并带读 | 因模型不输出像素而改用纯文字授课或要求换模型 |
| 客户端能显示图片但不解析 Mermaid | 提供渲染后的 PNG；图源保留供维护 | 只输出 Mermaid 并要求学习者自行看懂 |
| 授课模型没有执行工具，已有与当前版本一致的备课图片 | 引用这些图片，按已核对的图源与讲解带读 | 宣称不能图示教学；编造现场渲染成功 |
| 没有执行工具，也没有所需图片产物 | 如实说明备课资源缺失，临时解释可做部分，图片仍标待交付 | 假造图片地址；把缺资源归因于客户端不支持图片 |
| 渲染工具真实报错，或具体图片引用失败 | 检查工具/文件/引用；已有图可用则复用，否则临时文字并标明缺口 | 无限重试；把一次故障改成永久纯文本教学 |
| 只有 `.lesson-preview/` 的本地产物 | 使用实际可交付附件/资源；核对路径与版本 | 宣称另一机器或会话必然能访问本地路径 |
| 准备两份讲义，脚本都生成 diagram-01 | 使用各自独立输出目录，保持图源与产物对应 | 相互覆盖后仍把旧图当当前图 |
| 学习者说“这里显示的是绘图代码” | 交付渲染图片而非重复图源；把它当交付问题 | 否定已知的图片显示能力或判断学习者不懂 |
| 工具成功生成图片，但导师模型没有图像输入能力 | 据实记录渲染结果，引用已核验材料，视觉检查标未做 | 声称目视确认中文、布局或箭头；因此取消所有图片 |
| 图源已改、图片仍旧，或图文条件不一致 | 重新生成/选择匹配版本，修正练习依据 | 用过期图片证明新代码行为 |
| 要把个人轨迹发给未授权在线渲染服务 | 使用本地已配置工具或已有图，不上传；缺口如实记录 | 为了图片展示发送未授权私人数据 |
| 后续界面课缺少真实画面，却要求判断实际按钮位置 | 解释已知部分，标记真实视觉验收未完成 | 编造截图细节，或用机制图代替实际画面证据 |

## 静态与实际验证的边界

静态审阅检查材料和期望是否一致，不能证明模型实际遵守。独立模拟需保存合成输入、输出、问题和修订；真实教学需学习者实际参与。不调用付费模型、不改真实学习代码来伪装回归。

图文材料的可答性检查以当前实际交付的图片与附近说明为准，关注参与者、动作方向、状态、条件、依据是否明确。正常教学不要求每次移除图片做一套平行纯文本验收；临时故障才检查替代说明是否足以支撑当前问题。

图源静态检查、工具渲染、图片产物与引用检查、视觉检查、真实教学反馈分别报告。客户端支持图片是已知前提，不等于每个图片文件已创建或可访问；这也不是已实现的自动渲染/发布程序。以上表格是回归规格，不表示已运行独立试教或端到端测试。

本轮材料修订关注：保留图文教学，移除不符合用户条件的纯文本客户端分支，将缺现场工具与预先生成图片衔接。尚无新方式的真实学习效果数据，也未因修改规则就生成新图片资源。

## 真实试教如何判断改得对不对

先在 04.2 和随后一课观察：学习者能否说出为何学/为何问，能否找到判断依据，哪种提示有用，隔课能否处理一个近变体。记录具体例子，不以短期正确率或满意度单独宣称掌握。

课末只邀请一个轻量反馈，例如“刚才哪一步仍像在猜题？”；用户不想答则不强制。根据反馈改当前示范/题目，必要时再改通用规则。图片交付问题先修资源与呈现，不评价理解；不宣称视觉和文本教学效果已经等同。
