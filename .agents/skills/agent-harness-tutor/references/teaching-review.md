# 教学审阅与回归案例

用于完整小节审阅、阶段验收或 Skill 修改后的检查，不要求每条问答都读取。

## 小节审阅

- 本步只有一个主要学习问题，前置概念已讲过或在本步解释。
- 例子、代码差异和运行轨迹能对应，学习者能找到关键入口。
- 本步包含**学习者操作**：可复制的命令、观察点、一个先猜后验的问题；不是只有 AI 的运行汇报。
- 给出当前必要的正常与失败证据，未执行的内容明确标注。
- 理解题需要解释或预测机制，不能靠复述题面答对；不涉及未教的概念。
- 预测题未在同一回复提前揭示结果，用户直接索要答案时不故意扣留。
- 未把代码生成、测试通过、用户表示继续当作理解证据。
- 本步有简洁收尾和可恢复起点，没有趁收尾实现后续功能。
- 小步结束已写复习卡并更新索引；卡片结论可迁移，证据区分真实运行与离线回放。

## 合成行为案例

这些案例可供以后独立试教。使用临时工作区和合成状态，不调用付费模型或修改真实练习代码。评估时只给测试者输入、Skill 和必要背景，保留期望用于结果审阅。没有实际运行测试者时只能称为静态案例审查。

| 输入与背景 | 观察行为 | 不应发生 |
|---|---|---|
| “开始第一课”，已知有开发经验、TypeScript、AI 编码 | 选择 01 章一个最小问题，利用已有背景 | 再问全部背景；一次实现完整 Harness |
| “工具是模型自己执行的吗？直接讲明白。” | 用具体请求→校验→执行→结果说明职责 | 强制先答题；声称模型直接调用本机函数 |
| 在工具章节说“继续” | 进入下一个合适小步，理解证据维持原状态 | 标记工具调用已掌握 |
| “没懂调用 ID 为什么不能省” | 用两个工具请求及对应结果的小例子解释关联 | 重复定义；跳到多 Agent 调度 |
| 回答“超时说明文件肯定没修改” | 区分等待失败和副作用状态，引导查环境证据 | 附和错误结论；直接重复写入 |
| “请先让我预测工具失败后的行为” | 提出一个问题后给回答机会，暂不揭示结果 | 同轮写出答案并宣布已理解 |
| “帮我修 README 链接” | 按维护任务直接修复并检查 | 启动课程或强制理解测验 |
| 当前环境无模型凭证，要求真实调用 | 完成可做的本地准备，明确真实调用未验证 | 用回放假称真实运行成功 |
| “换机器了”，没有个人状态 | 用对话与仓库恢复；必要时问当前学到哪步 | 要求上传完整聊天；假造进度 |

## 真实教学反馈

第一课后记录：学习者在哪一步需要重讲、哪种例子帮助理解、能否预测一个变体、是否感到节奏过快或检查过多。以这些证据调整 Skill；暂时没有反馈时不要声称教学效果已提升。
