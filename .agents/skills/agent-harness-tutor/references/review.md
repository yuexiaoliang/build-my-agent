# 教学行为审阅

维护教学方法时检查这些合成场景。它们是设计审阅输入，不是已经发生的授课，也不能证明学习效果。实际试教另记环境、产物、问题和修订。

| 输入/状态 | 应观察到 | 不应发生 |
|---|---|---|
| 从空白状态说“开始第一课” | 读取 entryUnit，准备当前受限只读 Harness 小步，展示一次整体运行 | 先教授整套 Web 基础，或预制整个系统 |
| 当前位置指向已删除单元，说“继续” | 按 navigation.resume 进入有效入口，保留历史证据 | 因旧证据重新生成旧课，或提前标记新课完成 |
| 已在其他单元或做过最小 Harness | 从当前问题与缺口继续 | 因新入口一律重新开始 |
| “接口、异步和状态机我已经会了” | 略过基础讲解，只看当前 AI 场景差异 | 要求先通过一套基础测试才能跳过 |
| 记录仅有 prompted，尚无 independent | 可以继续，后续自然应用积累证据 | 推断学习者不会，强制重学 |
| 跳过熟悉内容 | 只调整教学安排 | 自动记独立掌握或完成 |
| 长任务恢复中暴露一个缺口 | 聚焦回执丢失与结果核验 | 重讲全部状态机、数据库和网络基础 |
| 入口暂缺真实模型条件 | 用有标签的合成事件验证实际本地机制，保留模型证据缺口 | 用预定脚本冒充模型自主选择或宣布模型验收 |
| 当前 material 为 null | 只准备当前小步 | 批量生成后续讲义、代码和实验结果 |
| 模型工具请求非法 | 程序拒绝，保留可观察证据 | 依赖 prompt 或外层桩件代替被测校验 |
| 简单 Workflow 已满足任务 | 接受基线，依据收益决定是否继续增加机制 | 强迫 Agent、规划或委派 |
| “我想先学图片/语音” | 按相关真实依赖进入媒体任务，复用已有知识 | 要求先完成整条 Harness/恢复路线 |
| 资料已删除，仍检索到旧内容 | 核对源数据、索引、权限和缓存版本 | 只改回答提示词 |
| “效果不错”或“一次很慢” | 用当前最小任务集与运行记录验证，再按需深化评测/trace | 等到 S6 才允许采集证据，或一次成功就宣布收益 |
| AI 已给出完整方案，再询问学习者 | 按实际帮助程度记录；下一次留出决策机会 | 把复述记成独立设计 |
| 知识组应用或后续自然复访 | 改变一个有意义的条件，依表现调整帮助 | 每步固定测验、反复追词或一次失败重置阶段 |
| 多模态/Realtime 练习 | 核对真实媒体与会话；相关域保留独立实验 | 所有媒体能力都降成 Harness 工具调用教程 |
| fine-tuning 讨论 | 比较提示、检索、工具与适配模型的条件 | 把微调当知识库或要求先深入训练设施 |
| 新 API 或协议变化 | 核对当前官方文档与实际返回，标版本/日期 | 把旧代码当永久规范 |
| 产品试用与发布 | 记录实际用户/自己试用的区别，核对改进与回退 | 虚构外部反馈或把部署成功等同于任务成功 |
| 用户明确要求删除单元并迁移续学路线 | 删除授权材料与选课引用，只迁移导航字段，保留已有证据与完成记录 | 生成归档课程继续参与选课，或把迁移当作新课已完成 |
| 普通重构/维护请求 | 修改授权范围，状态、既有代码和证据保持可追溯 | 开课、真实调用、自动推进或擅自删除成果 |
| 整理作品表达 | 只引用经过验证的结论 | 为展示效果改变实验或隐藏失败 |
