# 复习卡模板

每个小步结束时为学习者生成一张复习卡，保存在 `.learning/lessons/NN.M-短标题.md`，并在同目录 `INDEX.md` 增加一行。卡片属于个人记录：包含学习者的回答与判断，不提交公共仓库。公开教材需要时由卡片匿名化派生，不直接复制个人内容。

卡片目标是“几分钟内唤回这一步”，不是重抄教材；结论优先于过程。

````markdown
# NN.M · 短标题

- 日期：YYYY-MM-DD
- 本步问题：一句话
- 对应蓝图：第 NN 章（核心问题）
- 代码快照：提交号或 tag，或“无代码”
- 状态：已讲解 / 有解释或预测证据 / 有迁移证据 / 待复核

## 核心结论（可迁移）

- 3–6 条判据、边界或机制，每条一句话

## 关键代码与入口

- `path/to/file.ts:42` —— 作用；相对上一步的差异；重复代码进工具

## 运行证据

- `命令` → 关键输出；逐条标注 真实运行 / 离线回放

## 失败与反例

- 试过什么、失败在哪、说明了什么边界

## 我的判断与反馈要点

- 当时的回答；成立的部分与被修正的部分

## 未决问题

- 留待复核的点，也是 INDEX 中“待复核”的来源

## 下一步

- 下一个最小行动
````

写作要求：

- 只写有证据的内容；未运行、未验证的内容明确标注，不写“AI 说已完成”。
- 核心结论写成可迁移的判据或边界，不写“学会了什么”。
- 发现旧卡表述与新证据冲突时修改旧卡，并在 INDEX 中保留复核记录。

## 章末汇总

每章结束时把该章各卡聚合为 `chNN-汇总.md`，同样放在 `.learning/lessons/`，并在 INDEX 中单列一行。汇总不是复制卡片，而是按概念串线：

- 本章核心问题，以及每一步给出的部分答案。
- 概念线：本步结论如何依赖上一步（两三句即可）。
- 应能回答的问题清单：从各卡“未决问题”与核心结论改写成问题，用于自测。
- 跨章遗留：转到后续章节复核的点。

汇总同时作为跨机器复习与阶段验收的入口；需要公开教材时先从这里匿名化派生，再回溯各卡证据。
