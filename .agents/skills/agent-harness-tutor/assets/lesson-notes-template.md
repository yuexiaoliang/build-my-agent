# 讲义模板：导师提前准备，课堂逐段使用

每小步一份，放在 `docs/lessons/chNN/`。开章前准备问题、依赖、示范和练习分支；未来接口/实验标明计划。学习者只需当前必要片段，不需要把所有预写讲义读完。

下列是备课字段，不要求对话逐项打印。示范要给完整解释；练习答案可以折叠，但不能把教学内容也藏掉。

````markdown
# NN.M · 用真实问题作标题

> 状态：已备课 / 已实现 / 已离线验证 / 已真实调用（逐项据实）
> 为什么学：当前任务会在哪里失败，本步解决哪一个判断。
> 本步目标：学习者能依据什么，解释/判断什么。
> 位置：上一机制 → 本步 → 下一用途。
> 前置：只列直接依赖；缺失时在本页补，不默认发阅读包。
> 阅读范围：当前只需第几节；其他部分供回查。

## 1. 先看一个完整例子

具体输入 → 关键状态 → 代码入口 → 结果，逐步解释原因。
明确它是示意、静态走读还是实际运行。给一个“缺少该机制”的对照。
必要时用 Mermaid，不用图替代解释。

## 2. 现在换你判断一个小变化

- 为什么问/用途：本题对应的工程判断。
- 类型：机制推导 / 经验实验 / 设计取舍。
- 已知条件与依据：代码片段、字段、需求、预算、权限；先补未教前置。
- 问题：一次一个具体判断。
- 回答范围：例如结论加一处依据；不是猜导师想法。
- 支持：先定位观测点，再给最小对照，仍卡住则完整示范。
- 反馈：哪些依据成立；错在何处；什么时候换例子或补前置。

<details>
<summary>练习后对照：参考解释与成立条件</summary>

给依据、允许的其他合理答案、证据边界。不把设计偏好写成唯一答案。

</details>

## 3. 实现与验证（按本步需要）

AI 增量修改的范围、入口与关键差异；不提前实现后续机制。
已有命令、计划命令分开；计划命令不要当成可执行指令发送。
已有 fixture 用完整真实路径；新 fixture 创建后登记 INDEX。
分别写：解析回放能证明什么、完整运行能证明什么、还不能证明什么。

## 4. 收口与复访

本步结论及边界；一个变体及何时复访；下一步为何需要它。
讲义保持中性，个人证据进短复习卡，不重复长日志。

## 5. 验证记录

实际命令/代码版本/关键输出/fixture/结果范围。
未运行写未运行；运行记录不自动成为学习者理解证据。
````

备课时先检查题目是否真的服务目标；不为了填满模板发明题目或失败实验。短问答不套此模板。验证输出不能预写成已发生的事实。
