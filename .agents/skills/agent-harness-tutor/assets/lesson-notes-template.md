# 讲义模板：导师提前准备，课堂逐段使用

每小步一份，放在 `docs/lessons/chNN/`。开章前准备问题、依赖、示范和练习分支；未来接口/实验标明计划。学习者只需当前必要片段，不需要把所有预写讲义读完。

下列是备课字段，不要求对话逐项打印。示范要给完整解释；练习答案可以折叠，但不能把教学内容也藏掉。涉及角色、时序、状态或边界的新机制，按 Skill 准备图和邻近解释；同时使必要关系在纯文本中可理解。纯文本是完整教学路径，视觉是按可用能力提供的增强，不为简单问题凑图。

````markdown
# NN.M · 用真实问题作标题

> 状态：已备课 / 已实现 / 已离线验证 / 已真实调用（逐项据实）
> 为什么学：当前任务会在哪里失败，本步解决哪一个判断。
> 本步目标：学习者能依据什么，解释/判断什么。
> 位置：上一机制 → 本步 → 下一用途；用已有任务地图或编号链突出本步。
> 前置：只列直接依赖；缺失时在本页补，不默认发阅读包。
> 阅读范围：当前只需第几节/哪张图或对应文本步骤；其他部分供回查。

## 1. 先看一个完整例子

具体输入 → 关键状态 → 代码入口 → 结果，逐步解释原因。
明确它是示意、静态走读还是实际运行。给一个“缺少该机制”的对照。

### 图和文字一起讲什么

- 图的用途：要看清哪一种关系或变化，选择结构/时序/状态/前后对照；排障必要时用真实局部截图或输出片段。
- 图示及边界：Mermaid 图源写在本节；标明当前实现、合成示意或未来计划，指出省略条件。有可用显示通道时呈现渲染图；否则用下面的文本表示，不让学习者读绘图语法。
- 读图入口：从哪里开始，沿哪个编号/箭头走；用一句话说明形状、连线含义。
- 邻近讲解：用具体输入沿图解释一条正常路径，再加一个变化；不把所有分支一次铺开。
- 落到实现：图中节点/字段 → 同一个例子的代码入口 → 相应输出或证据。命名、调用 ID 和字段值保持一致。

### 无视觉输出时怎样讲同一件事

复用本页已有说明，必要时补一份简短编号轨迹或字段/状态对照，不另生成一套文件。它需要保留本步用到的参与者、方向、顺序、条件、状态变化、失败分支及证据入口。编号与图一致，题目引用编号或字段名，不只说“右侧框”“红色箭头”。

默认：能内联渲染则使用；不能内联但有可用渲染工具和图片交付通道则由 AI 提供文件；仅能文本输出或能力未知则直接带读文本。能生成图源、能渲染、能向学习者显示不是同一种能力，不互相推断。无需安装渲染工具、访问新站点或更换模型即可继续机制教学。

默认先聚焦一张主图或一份文本轨迹，不同时展示重复的多种表示。前后对照依次讲，完整字段表可折叠；不支持折叠时由导师控制呈现范围。图不是另一份阅读作业，不只是把长段文字塞进方框。短局部问题用文字、字段表或代码即可。

## 2. 现在换你判断一个小变化

- 为什么问/用途：本题对应的工程判断。
- 类型：机制推导 / 经验实验 / 设计取舍。
- 已知条件与依据：当前实际交付的代码、图/文本步骤、字段、需求、预算、权限；先补未教前置。
- 问题：一次一个具体判断。可按编号定位，不要求背图或重画整图。
- 回答范围：例如结论加一处依据；不是猜导师想法。
- 支持：先定位观测点，再给最小对照，仍卡住则完整示范。
- 反馈：哪些依据成立；错在何处；什么时候换例子或补前置。图或文字已展示的结论不算独立迁移证据。
- 可答性检查：移除所有图片/图源后，文本路径仍提供本题必要条件吗？否则先补材料，不把显示故障判为理解失败。

给依据、允许的其他合理答案、证据边界。不把设计偏好写成唯一答案。客户端不能折叠时，练习阶段不同时发送此段，学习者要求答案时照给。

## 3. 实现与验证（按本步需要）

AI 增量修改的范围、入口与关键差异；不提前实现后续机制。
已有命令、计划命令分开；计划命令不要当成可执行指令发送。
已有 fixture 用完整真实路径；新 fixture 创建后登记 INDEX。
分别写：解析回放能证明什么、完整运行能证明什么、还不能证明什么。

## 4. 收口与复访

本步结论及边界；回到图或编号轨迹中变化的连接；一个变体及何时复访；下一步为何需要它。
讲义保持中性，个人证据进短复习卡，不重复长日志或为每张图另建文档。

## 5. 验证记录

实际命令/代码版本/关键输出/fixture/结果范围。
未运行写未运行；运行记录自动成为学习者理解证据是不成立的。
分别记录：图源静态检查、实际渲染、交付通道核对、视觉检查、纯文本路径检查、真实学习反馈。哪些未做就写未做；模型不能查看图像时，不声称检查了布局。能生成文件不证明学习者已在对话看见它。
````

备课时先检查题目是否真的服务目标；不为了填满模板发明题目或失败实验。短问答不套此模板。验证输出不能预写成已发生的事实。

## 纯文本示例：不是“见图”，而是保留关键状态

下面是桥接课正常路径的合成摘录，不是新运行结果。沿用该课编号与调用 ID，前提为请求合法、预算足够且没有重复停止。它只演示第 5–7 步的信息位置变化；其他前置仍由本课说明。

```text
第 5 步：文件系统 -> Harness
返回“先备份，再导入”。此时结果在本地，还没放进下一次请求。

第 6 步：Harness 更新 messages
追加 assistant 的工具请求和 tool 结果，使用同一个 call_demo 关联。
此时下一次请求的数据已经准备好，但尚未发送。

第 7 步：Harness -> Model
发送更新后的 messages，工具结果随这次请求提供给模型。
```

带读时解释“读到结果、准备请求、发送请求”三件事。随后的小变化仍须先说明用途，再给“只打印终端、没有回填且没有其他信息渠道”等条件，邀请定位缺失动作；不能把未传输与模型一定答错混为一谈。

机制图是同一个故事的另一种表示。更换媒介不减少前置、反馈或任务要求，也不宣称两种形式的学习效果已证明等同。

## 图文审阅场景

- “图看不懂”：先分辨未显示还是关系难懂；前者改文本，后者解释角色、连线和阅读方向，只追踪一个具体值。
- 讲 Loop 或恢复只有长文字：有视觉能力时补时序/状态图；纯文本时整理为编号步骤和状态对照，而不是只追加“必要时画图”。
- 模型仅输出文本、客户端支持 Mermaid：仍可交付文本图源由客户端渲染，不能因模型不出图片就放弃。
- 客户端不能显示图片/附件、没有执行工具或能力未知：当前对话交付完整文本路径，不只给图源或网页链接，不让安装工具阻断学习。
- 图已经包含练习答案：明确它是有支持的练习，独立迁移另用变体，不能把看图复述当掌握证明。
- 示意图被称为“实测”：纠正证据类型，不能虚构截图、输出或学习反馈。

视觉检查关注中文、箭头、拥挤程度和不依赖颜色的可读性。现有预览脚本为 `scripts/render-diagrams.sh`；先核对当前执行环境，无能力则记录未验证，不因为图源存在宣布显示正常。纯文本检查关注仅靠当前文本能否说明本步关系、完成练习；实际界面视觉验收仍需真实观测，不以文字替代后声称已验证。
