# 讲义模板：导师提前准备，课堂逐段使用

每小步一份，放在 `docs/lessons/chNN/`。开章前准备问题、依赖、示范和练习分支；未来接口/实验标明计划。学习者只需当前必要片段，不需要把所有预写讲义读完。

下列是备课字段，不要求对话逐项打印。示范要给完整解释；练习答案可以折叠，但不能把教学内容也藏掉。**学习者已明确客户端一定能显示图片。** 涉及角色、时序、状态或边界的新机制，准备实际图片和邻近讲解；模型只输出文本不是取消图示的理由。短定义与局部问题不为形式凑图。

````markdown
# NN.M · 用真实问题作标题

> 状态：已备课 / 已实现 / 已离线验证 / 已真实调用（逐项据实）
> 为什么学：当前任务会在哪里失败，本步解决哪一个判断。
> 本步目标：学习者能依据什么，解释/判断什么。
> 位置：上一机制 → 本步 → 下一用途；用已有任务地图突出本步。
> 前置：只列直接依赖；缺失时在本页补，不默认发阅读包。
> 阅读范围：当前只需第几节/哪张图；其他部分供回查。

## 1. 先看一个完整例子

具体输入 → 关键状态 → 代码入口 → 结果，逐步解释原因。
明确它是示意、静态走读还是实际运行。给一个“缺少该机制”的对照。

### 图和文字一起讲什么

- 图的用途：要看清哪一种关系或变化，选择结构/时序/状态/前后对照；排障必要时用真实局部截图或输出片段。
- 图示及边界：Mermaid 图源保留在本节供维护；课堂展示渲染图片，不只交付图源。标明当前实现、合成示意或未来计划，指出省略条件。
- 读图入口：从哪里开始，沿哪个编号/箭头走；用一句话说明形状、连线含义。
- 邻近讲解：用具体输入沿图解释一条正常路径，再加一个变化；不把所有分支一次铺开。
- 落到实现：图中节点/字段 → 同一个例子的代码入口 → 相应输出或证据。命名、调用 ID 和字段值保持一致。

### 图片备课与交付

- 图源位置：本页对应的 Mermaid 块；与代码/讲义的版本关系。
- 图片产物：实际生成后填写文件位置和已核对的图片引用/附件；未生成写“待生成”，不虚构地址。
- 生成方式：模型输出图源，由已配置的渲染工具生成 PNG；已确认支持其他格式时可用。客户端支持图片不等于内置 Mermaid，不把内联 Mermaid 作为必需能力。
- 课堂使用：关键图优先在备课阶段生成并核对；授课模型没有执行工具时引用这些产物，有工具时才按需要增量渲染新图。
- 实际缺口：本地预览是否已交付、图片是否仍对应当前版本；不能把仅有图源或旧图当作配图已完成。

默认先聚焦一张主图和附近解释。前后对照依次讲，完整字段表可折叠；不支持折叠时由导师控制呈现范围。图不是另一份阅读作业，不只是把长段文字塞进方框。

文字需要解释参与者、动作、关键状态与条件，便于读图和复习，不必另抄一份完整平行教材。真实发生渲染/文件/引用故障时，可以临时改用同编号轨迹，但须注明图片交付未完成；不将故障误说成客户端不支持图片。

## 2. 现在换你判断一个小变化

- 为什么问/用途：本题对应的工程判断。
- 类型：机制推导 / 经验实验 / 设计取舍。
- 已知条件与依据：当前实际交付的代码、图片、字段、需求、预算、权限；先补未教前置。
- 问题：一次一个具体判断。按编号、字段或动作定位，不只用颜色/坐标，不要求背图或重画整图。
- 回答范围：例如结论加一处依据；不是猜导师想法。
- 支持：先定位观测点，再给最小对照，仍卡住则完整示范。
- 反馈：哪些依据成立；错在何处；什么时候换例子或补前置。图或文字已展示的结论不算独立迁移证据。
- 可答性检查：当前已经交付的图文是否提供本题必要条件？实际发生图片故障时先补齐临时说明，不把材料缺失判为理解失败；不要求正常图文课堂每次移除图片再讲一遍。

## 3. 实现与验证（按本步需要）

AI 增量修改的范围、入口与关键差异；不提前实现后续机制。
已有命令、计划命令分开；计划命令不要当成可执行指令发送。
已有 fixture 用完整真实路径；新 fixture 创建后登记 INDEX。
分别写：解析回放能证明什么、完整运行能证明什么、还不能证明什么。

## 4. 收口与复访

本步结论及边界；回到图中变化的连接；一个变体及何时复访；下一步为何需要它。
讲义保持中性，个人证据进短复习卡，不重复长日志或为每张图另建文档。

## 5. 验证记录

实际命令/代码版本/关键输出/fixture/结果范围。
未运行写未运行；运行记录自动成为学习者理解证据是不成立的。
分别记录：图源静态检查、实际渲染、图片产物与引用检查、视觉检查、真实学习反馈。哪些未做就写未做；模型不能查看图像时，不声称检查了布局。客户端支持图片是已知前提，具体图片能否访问与版本是否一致仍需核对。
````

备课时先检查题目是否真的服务目标；不为了填满模板发明题目或失败实验。短问答不套此模板。验证输出不能预写成已发生的事实。

## 渲染环境约定

现有 `scripts/render-diagrams.sh` 提取讲义中的 Mermaid，再调用 `mmdc` 生成 PNG；要求 Bash、可用的 Chrome/Chromium 和 Mermaid CLI。每份讲义使用独立输出目录，避免脚本的 `diagram-01` 等文件名互相覆盖。配置依赖由课程维护阶段完成，不交给学习者作为课堂作业。

默认 `.lesson-preview/` 仅是本地预览，不能把它当作已经发布的图片库，也不能假设别的机器或会话能打开该路径。实际授课时使用可交付的图片附件或已核对的资源引用。正式图需保留图源与对应版本；本次模板修改没有生成或发布这些资源，不声称自动渲染/发布流程已经实现。

没有现场执行工具时先复用备课图片；没有图片或生成失败时如实报告缺失，临时用文字维持解释，但保留配图待完成状态。不要求模型原生生成像素、不让学习者读 Mermaid，不擅自使用会上传个人数据的在线渲染服务。

## 临时故障讲解示例

仅在实际图片产物/引用故障时使用下面的合成摘录，平时作为读图说明即可。它沿用桥接课编号，前提为请求合法、预算足够且没有重复停止；不是新运行结果。

```text
第 5 步：文件系统 -> Harness
返回“先备份，再导入”。此时结果在本地，还没放进下一次请求。

第 6 步：Harness 更新 messages
追加 assistant 的工具请求和 tool 结果，使用同一个 call_demo 关联。
此时下一次请求的数据已经准备好，但尚未发送。

第 7 步：Harness -> Model
发送更新后的 messages，工具结果随这次请求提供给模型。
```

讲清“读到结果、准备请求、发送请求”的区别；后续题目引用编号和条件。临时文字解释不等于图片已交付，也不证明实际界面上的视觉状态。

## 图文审阅场景

- 用户已经确认客户端能显示图片：不再询问或设计常规纯文本客户端分支，重点检查渲染与图片交付。
- 模型只输出文本：生成图源交给工具，或引用预先渲染的图片，不因缺原生出图能力取消图示。
- 客户端显示图片但不解析 Mermaid：展示渲染后的 PNG，而不是只输出绘图语法。
- 授课模型无执行工具：引用与当前材料匹配的备课图片，不编造已运行渲染器。
- “图看不懂”：关系未理解时解释参与者、连线和方向；图片实际加载失败时修复资源引用，必要时临时带读文字。
- 图已经包含练习答案：明确是有支持的练习，独立迁移另用变体。
- 示意图被称为“实测”，或模型不能看图却声称已目视检查：纠正证据类型。

视觉检查关注中文、箭头、拥挤程度和不依赖颜色的可读性。实际界面验收仍需真实观测，不以机制图或文字代替后声称已验证。

工具依据（维护者查阅）：[Mermaid CLI 官方说明](https://github.com/mermaid-js/mermaid-cli)。官方功能支持与本课程实际生成/交付状态分开记录。
