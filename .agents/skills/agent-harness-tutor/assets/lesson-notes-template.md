# 讲义模板（每小步一份）

每章开始前，按本模板为该章各小步预写讲义**主干**，存放到 `docs/lessons/chNN/NN.M-标题.md`。只写主干：问题、前置、原理、图、代码导读、验证命令、预测题（**只写问题，不写答案**）。课中动态产生的实验、学习者预测与实测落差，课后回填到"验证记录"一节——讲义既是规划，也保留适应性。

读者是学习者本人，也是公开读者：不写个人判断与进度（那些进 `.learning/` 复习卡）；运行证据可以引用 fixtures/ 中的录制文件。

```markdown
# NN.M · 标题

> **本步问题**：一句话。
> **前置**：需要先理解的概念（引用讲义或复习卡）。
> **蓝图对应**：第 NN 章（核心问题）。

## 1. 目标与可观察任务

完成后系统多会什么；运行时能观察到什么现象。

## 2. 原理与执行轨迹

机制讲解。时序、状态流、并发关系用 Mermaid 图（GitHub 直接渲染；本地用 `scripts/render-diagrams.sh` 渲染成 PNG）。类比要指出适用边界，再落回真实机制。

## 3. 实现与差异导读

相对上一步改了哪些文件；关键入口（`path:行号`）、输入输出。只讲本步差异，不提前堆未来机制。

## 4. 验证

- 命令清单，**真实运行 / 离线回放分别标注**。
- **预测题**：只写问题，不写答案；课堂上先答后跑。
- 一条与本步概念有关的失败路径。

## 5. 验证记录（课后回填）

- 实际输出摘录、fixture 路径。
- 学习者的预测与实测落差；临时追加的实验及原因。

## 6. 小结

一句话结论；指向下一小步。
```

写作要求：

- 每步只围绕一个主要问题；新术语首次出现时用中文解释并附英文名。
- 区分计划、模拟输出、真实运行；没跑过的命令不得写成已验证。
- 图宁少勿滥：只对时序、状态流、结构关系画图，能用表格说清的用表格。
