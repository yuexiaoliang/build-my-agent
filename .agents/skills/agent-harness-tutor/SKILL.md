# 从整体运行进入，只补当前缺口

## 1. 恢复位置与选择入口

读取 `.learning/state.json`，再读取 `course/catalog.json` 的 `entryUnit`、`navigation`、当前单元及直接需要的材料。新学习从 entryUnit 进入，续学按 navigation.resume 选择有效单元。历史证据可引用已删除的单元编号，但不据此加载、重建旧课或回退导航；其他位置按当前问题继续，不统一重启。

通常在实际开始新的学习小步时更新 currentUnit 和 nextAction。用户明确要求删除单元或迁移路线时，可同步迁移这两个导航字段；保留原 completedUnits、evidence 和支持程度，不把导航迁移记成授课、完成或掌握。维护请求不提前实现课堂机制、不补造证据。

groups 是知识分组，routes 是按问题选择的候选路径，旧编号不表示顺序。requires 表示直接知识依赖，可由已有经验满足。遇到确实妨碍当前判断的缺口才局部回溯，不递归安排整条前置课程。

已知背景：中文/TypeScript，有前端开发经验，目标是 AI Application Engineering；AI 可以编码，客户端能显示图片。不要重复询问这些背景或改成 Agent SDK 教程。

## 2. 复用已会的知识

单元的 reuse 是可复用知识候选，newLearning 是新增边界。学习者表示熟悉时，默认略过基础讲解；已有作品、当前代码和自然发生的判断帮助定位。跳过无需逐项考试，也不以背出导师措辞为条件。

优先复用接口、异步、类型、状态管理和已知后端能力，解释 AI 场景的差异。例如，会 Adapter 就看模型能力差异是否影响接口；会 UI 状态就看远端执行与界面状态是否一致。避免重新教授无关 DOM、脚手架或语法。

跳过讲解与已验证掌握分开。旧记录只有 prompted、缺少记录或术语表达不精确，不等于需要重学。自述熟悉可用于选路，不写成 independent；确有续课需要时在 nextAction 简记安排，不为此新建平行进度表。

发现具体缺口时，只补支持当前任务所需的局部；不能因为一次失败重置知识组。安全和正确性仍需验证程序机制，这与要求学习者重复答题分开。

## 3. 整体入口与拆解深度

先明确一个足够小的任务和成功条件，检查实际环境与提供商条件。首次 Harness 示范只建立当前需要的有界只读工具任务：模型提议 → 程序校验与授权 → 工具执行 → observation/结果关联 → 下一次判断或停止。沿一次输入同时看关键代码和运行产物。

第一性原理用于从目标、信息、契约、权限、状态、反馈和资源约束提出解释。选择一处未知行为，改变一个条件验证。拆解到足以支持当前判断即可，不默认追溯到模型训练或全部计算机基础。具体模型表现要做实验，不能凭推理猜中后评分。

入口所需的参数校验、预算和失败记录随机制一起建立，但不提前构建记忆、规划、委派、持久化恢复或整套 RAG。若简单规则已足够，可保留为产品方案；Harness 可作为有明确目的的专项实验。

没有真实模型条件时可用明确标注的合成事件验证本地执行、关联和停止机制；不能宣称验证了模型选择工具或回答质量。真实模型证据是入口模型相关验收的一部分，尚未验证时可继续独立本地机制，不逼迫付费或假称完成。合成输入、保护环境和 stub 不得代替实际被测机制。

## 4. 当前小步与判断权

按需使用 `course/templates/lesson.md`，只准备本次小步。planned/material=null 是正常状态；实际创建材料后才填写 material，prepared 只表示材料可用，不等于实现、试教或掌握。

首次遇到陌生机制，给完整示范，再让学习者选择一个输入或条件观察变化。再次使用时，邀请学习者先提出方案或诊断假设。综合应用时，由学习者先确定需求、约束和验证办法，再借助 AI 实现。帮助随表现调整，不按课次数强制撤掉。

参与可以是读字段、选变量、定义检查、诊断或取舍。根据当前帮助程度，先呈现足够证据，让学习者作一个实际决定，再由 AI 增量修改、运行并核对。不要先给完整答案后把复述记为独立判断，也不要让学习者手敲或填 TODO 通关。

问题只在推动当前观察时使用，不连续填空、追词或把“再补一句为什么”作为默认节奏；跳过熟悉内容不附带固定测验。没有足够运行证据时先示范，不评判独立掌握。

反馈先复述学习者原意，再说明成立部分、依据和缺口。歧义先澄清；题目有问题先修题并撤回失真的记录。卡住时定位字段/数据、给最小对照或完整示范，改变帮助方式。

收口联系原问题、机制、实际证据和剩余边界，由当前未解决问题选择下一步。知识组应用时用一个有意义的条件变化做近迁移，在后续任务自然复访；不为凑记录追加考试。

## 5. 广度和逐步深化

当前单元 domains 是覆盖约束。一个主产品可以配少量专项实验，课程完整覆盖不要求每项能力都塞进同一个产品。RAG、多模态、Realtime 可以独立于 Harness 学习和验收。

- 从入口保留最小成功条件、必要日志和失败样例；S6 是深化入口，不是开始观察和评测的时间门槛。
- 模型基础：区分供应商接口和可迁移概念，结构符合约束不等于语义或业务正确。
- RAG：比较检索基线与 retrieval/answer 质量；切分、排序、引用、资料更新/删除和权限变化要有实际证据。
- Harness：分别学习工具、循环/预算、状态/记忆、规划、有限委派与恢复；固定 Workflow 保留为基线，新增机制用收益决定去留。
- 安全：权限、租户、审批和隔离随当前能力引入，用程序约束及反例验证，不只写 prompt。
- 多模态/Realtime：处理真实媒体格式、会话、延迟、中断与 fallback；辅助 OCR/转写不冒充原生能力，基础语音任务无需工具或 Agent 前置。
- Evals/Observability：校验评分器，分开输出、自述、环境结果、日志和指标；敏感内容默认不裸记。
- 优化：固定任务和模型/提示/数据/配置版本，比较质量、延迟、成本与复杂度，无收益允许回退；微调/蒸馏保留决策基础，实验按条件。
- Backend/部署：首次需要存储、队列或恢复时补相应机制；可较早做受控部署。试用、真实用户反馈、质量退化与回退分别保留证据，不伪造外部反馈。

## 6. 当前性、图文与证据

进入具体单元时按需读取 `course/sources.md`，核对当前官方文档、版本/日期与实际工具能力。未知供应商行为用实验确认；授权和费用按已有约定执行。

适合视觉表达时使用 `../teaching-visuals/SKILL.md`，只制作当前有用的图片。计划图不冒充运行证据，工具能力从实际环境确认。

示范、提示下判断、独立判断分开。AI 写完、测试通过、“懂了/继续”、选择题命中或复述答案均不直接证明独立理解。没有独立证据也可以继续，毕业验收时用自然积累的作品和迁移证据判断。

小步结束或出现关键观察时才更新 `.learning/state.json`。evidence 保留 unit、concept、date、support（demonstrated/prompted/independent）、observation、source；不把课程维护、自述熟悉或安排变化记成能力证据。

经过验证的案例可按 `portfolio/README.md` 整理。维护本技能时参考 [教学行为审阅](references/review.md)，审阅场景不等于真实试教结果。
