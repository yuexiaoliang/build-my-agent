# Harness 能力与验收矩阵 v0.3

这是课程目标，不是已获得的能力证明，也不是任何公司的招聘评分表。目标以 Harness 研发工程能力为主，研究进阶单列。与职位对标前需另查官方职责、方向与资历要求，招聘转载不能作为课程验收标准。

## 两种证据分开验收

作品证据：代码、命令、实际轨迹和独立结果检查。例如解析器保留字段，只证明解析路径具备该能力，不直接证明整个 Loop 遵守策略。

学习证据：学习者在一个具体任务中说出了什么判断，使用什么依据，获得什么提示，适用于什么范围。导师答案、生成文档、测试通过、选择题猜中和“继续”不能替代这类证据。

## 一个概念的掌握如何判定

不是每步出固定数量的题，而是在相关任务中累积以下证据：

| 观察 | 可记录的结论 | 接下来怎么教 |
|---|---|---|
| 只能跟随完整演示 | 已讲解/跟随示范 | 再给一个小变体和明确入口 |
| 在提示下能指出关键因果 | 有解释/预测证据，提示后 | 换同层次例子，逐渐撤掉提示 |
| 能独立判断未直接示范的近变体，并指出代码/环境依据和边界 | 该概念在注明范围内有独立应用证据 | 进入依赖它的内容，安排自然复访 |
| 隔课再次使用仍能解释，或能迁移到不同任务 | 有保持/迁移证据，注明任务与范围 | 扩大问题范围，不因一次表现推断全局掌握 |

区分“会查资料完成工程判断”和“无需提示能回想”。开卷、运行或让 AI 写代码都允许；若导师已给出关键判断，不能再记为独立证据。正式阶段验收前说明目标、可用帮助、验收场景与结果如何解释，不能临时藏条件。

缺少迁移证据时记录待复核，不把一次课堂变成无限通关。用户要求继续可以推进；关键安全或直接前置尚不清楚时，先提供必要的保守边界和最小补课。无效或含糊题不能用来评价能力，须先修题。

## 分阶段理解标准

入门：看懂关键代码，复述轨迹并预测给定条件变化；不考未知供应商行为的猜测命中。

工程：面对失败提出可区分的假设，选择日志或环境观测，用实验排除错误解释。不强造两个原因凑数；“证据不足以判断”可以成立。

独立研发：在 AI 提供完整方案前确定需求、约束和评测方法；能指出方案的证据缺口，指导修改并拒绝无依据的“成功”。设计题允许多个有依据的方案。

研究进阶：从已有系统局限提出可检验假设，在固定预算和独立任务上验证，能够报告没有改善的结果。

所有层次允许 AI 编写代码、测试与报告草稿。支持程度按具体概念和新任务调整，不因章节变高级就禁止完整示范。

## 作品证据包

每阶段保存任务说明、代码与环境版本、运行命令、轨迹、独立结果检查、失败记录及学习者复盘。真实调用附模型配置、样本数量及费用；离线回放单列并说明实际覆盖路径。

最终产物包括核心运行时、开发者 Agent、三类迁移实践、评测平台及三份实验/诊断报告。按蓝图毕业要求验收，不按功能数量、上游 PR 合并数或单次演示成功判定。

## 能力边界

课程提供系统实践，不替代操作系统、网络、并发、数据库等基础；缺口按当前任务补最小前置。研究方向需要额外实验训练，完整模型训练和大规模推理设施属于另一条专业路线。

不承诺通过 DeepSeek、月之暗面或其他企业招聘。岗位对标需区分官方原文、转载、课程判断与未验证内容，并注明日期。旧学习记录继续有效，新矩阵不追溯制造、升级或降级个人能力状态。
