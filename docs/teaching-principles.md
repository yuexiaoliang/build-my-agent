# 教学与学习原理：从原则到动作

本页供导师备课和维护，不是学习者的必读材料。研究为设计提供依据，不保证在单学习者 Agent Harness 课程中的效果；下面的课堂安排是可调整的设计选择，不是统一效应量或诊断结论。

## 先示范，再逐渐交还判断

新机制先用完整的具体例子解释输入、状态和因果，再做有支持的小变体，最后才做更独立的迁移。原理、图和真实代码相互对应，不能只列术语或只展示结果。

工作样例、抽象与具体表示的连接、解释性提问和间隔复习，是 IES/WWC 指南分别讨论的做法。该指南对不同建议给出的证据等级不同，不能把它们打包说成“效果已经证实”。这里采用它们设计课堂，而不是要求学习者阅读研究。[来源：Organizing Instruction and Study to Improve Student Learning，2007](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)。

## 纠正“先猜再跑”的过度泛化

回想已学知识、根据给定代码推导、对未知模型行为做预问，是不同活动。前者可作为提取练习；第二种练因果推理；第三种可以引出好奇与假设，但不能仅凭命中结果给能力打分。

没有前置知识时先教学，不以“合意困难”为由制造盲猜。不开卷、延迟反馈或答错都不天然有益；教学需要时即时解释，学习者要求答案时给答案。复习题应围绕已学关键内容，并在隔课或再次使用时复访，而不是每个操作强行提问。

## 支持按概念证据调整，不按章节撤除

同一个学习者可能熟悉 HTTP，但不熟悉调用 ID；熟悉 Loop 后遇到恢复语义又需要完整示范。观察的是某个概念下的独立判断、提示程度和迁移边界，不能因进入“高级章节”就禁止示例或 AI 编码。

形成性反馈要改变下一步：指出具体依据 → 定位缺口 → 给恰当支持 → 再观察。若只是判对错然后按原计划推进，就没有形成有效的教学调整。一次答对的意义受题目难度、提示和猜测影响。

## 有意义的任务与可见的标准

每个练习连接真实工程判断，说明用途、依据与回答范围。设计题先给约束，可有多个成立方案；经验实验允许“不足以判断”。“不知道为什么学/为什么问”是教学需要调整的信号，不是学习者缺乏自觉的证据。

一步聚焦一个主要问题，但不把它机械变成固定字数、固定段数或一问一批准。备课详尽、呈现克制；减少无关阅读，不减少必要解释。

## 不应发生的事

只汇报 AI 的结果；整章文档代替教学；未教先考；无限追问；选项猜中即标记掌握；把供应商偶然行为当通用规律；把学习者的简答推断为态度问题；为每次反馈追加一条全局硬规则。

发现问题时先改当前题目、示范或材料，检查实际体验后再决定是否扩大修改。教学规范见 Skill，具体回归案例见其 `references/teaching-review.md`。

## 质量证据

分别记录：目标/题意是否清楚；是否能指出依据；用了什么提示；补救后是否理解；隔课能否复用。不要以文档数量、题目数量、章节百分比或纯预测命中率代表教学质量。

本次 v0.3 修改只完成材料与规则层面的设计和静态审阅。真实学习效果必须由后续课堂反馈检验，不能由安装 Skill 或规则检查推定。
