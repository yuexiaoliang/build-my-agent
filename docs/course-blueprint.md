# 渐进式课程蓝图 v0.2

状态：设计稿，2026-09-11 更新。章节规格不代表教材或功能已经实现。v0.2 将企业业务主线改为通用 Harness 与开发者 Agent；企业系统保留为迁移环境。

## 目标与范围

学习者能够解释、设计、诊断、改进和维护 Agent Harness。主线采用 TypeScript，面向有开发经验的中文读者；代码、测试和实验脚本由 AI 按课程增量实现。

本课程将 Harness 定义为模型之外，组织上下文、工具、执行环境、状态、控制流及交互的运行系统。评测平台与运行时分开实现，通过稳定接口组合。模型训练和推理基础设施介绍协作边界，不将完整预训练、GPU 集群或分布式推理引擎纳入必修实现。

贯穿任务：“理解练习仓库，修复一个导入功能缺陷，补充验证并说明改动。”从只读查询开始，逐步支持受控编辑、命令执行、长程任务和协作。初期使用 CLI，后期增加运行轨迹与人工介入界面；不以复制成熟产品全部功能为目标。

最终交付：可复用 Harness、开发者 Agent、共用核心的迁移实践、独立评测平台，以及包含失败结果的技术报告。能力对应关系见[验收矩阵](competency-matrix.md)。

## 预备篇与增量边界

按诊断选读 TypeScript 类型与异步、HTTP/JSON、Git、测试、环境变量、文件与进程基础。进入后续章节前按需补充事件循环、并发、事务和隔离，不在第一课堆叠全部前置知识。

每章拆为多个小步，每步围绕一个主要问题。AI 编写当前所需代码并展示差异，学习者预测或解释行为。工具从只读开始；引入写操作和命令执行时，同步建立对应权限与执行边界。评测与事件记录从第一阶段出现，后期深化。

## 阶段一：理解基本机制（01–05）

| 章 | 核心问题 | 增量成果与验收证据 |
|---|---|---|
| 01 任务与模型 | 哪些任务需要 Agent？ | 一次模型调用与明确标注的离线回放；能解释普通程序、工作流和 Agent 的选择；缺配置、请求失败可辨认 |
| 02 工具契约 | 模型请求如何成为合法行动？ | 合成练习文件的只读查询工具；参数、路径与未知工具校验；无效请求不执行 |
| 03 Agent Loop | 如何根据观察继续行动？ | 调用 ID 关联、工具结果回填、有界循环；两步任务完成，重复调用和步数耗尽有明确结果 |
| 04 消息与协议 | 模型输出怎样变成应用状态？ | 消息适配、结构化输出校验、截断与错误分类；不把损坏输出当成功，不假设不同模型协议完全一致 |
| 05 最早的评测 | 跑通一次意味着什么？ | 事件轨迹、固定任务和离线回归；真实调用单独记录模型配置、成功数、总数及失败原因 |

## 阶段二：构建可控运行时（06–12）

| 章 | 核心问题 | 增量成果与验收证据 |
|---|---|---|
| 06 文件编辑 | 怎样约束和验证修改？ | 受限编辑工具、补丁前置条件与差异查看；路径穿越、符号链接越界和陈旧内容修改被拒绝 |
| 07 进程与执行隔离 | 如何运行命令并限制影响？ | 在预置隔离环境运行测试，管理子进程、输出、超时与资源；超时清理进程树，解释路径校验与系统隔离的区别 |
| 08 流式事件与取消 | 用户停止后谁还在工作？ | 增量输出、取消传播、慢消费者与输出限额；取消后不再启动新工具，未能终止的动作有明确状态 |
| 09 权限与人工介入 | 谁能授权什么动作？ | 动作绑定的审批与可信身份、最小权限、日志脱敏和注入用例；不可信文件不能授予权限，参数变化需重新审批 |
| 10 会话与事件持久化 | 重启后怎样知道发生过什么？ | 版本化事件记录与会话恢复；处理不完整日志和重复事件；区分事件回放与重新执行副作用 |
| 11 执行恢复 | 环境与日志不一致怎么办？ | 检查点、结果核对、重试分类；在写成功但确认丢失时避免盲目重做，无法确定时交给用户处理 |
| 12 扩展与工具接入 | 如何替换能力而不破坏运行时？ | 最小插件生命周期、配置校验和同一只读工具的 MCP 适配；加载失败可定位、卸载释放资源、权限不扩张 |

## 阶段三：可靠完成复杂任务（13–20）

| 章 | 核心问题 | 增量成果与验收证据 |
|---|---|---|
| 13 项目搜索与上下文选择 | 仓库太大怎样获取必要信息？ | 先文本搜索基线，再按需读取和工具输出截断；缺失证据时继续检索或说明限制，记录来源 |
| 14 压缩与缓存 | 压缩节省了什么，又丢了什么？ | 上下文预算、摘要与原文回取、稳定前缀实验；检查关键约束保留率；解释 KV Cache 与应用缓存边界，不假造不可观测命中率 |
| 15 记忆 | 什么值得跨任务保留？ | 会话、任务状态和长期记忆分离；来源、更新、过期、删除与隔离；过期或恶意记忆不直接成为可信指令 |
| 16 规划与工作流 | 何时动态决策，何时固定步骤？ | 同一任务比较简单循环、显式流程和计划；计划可修订，完成判断依赖环境证据 |
| 17 长程任务 | 如何发现停滞与任务偏离？ | 跨会话进度、阶段检查、预算、交接；注入上下文丢失与循环停滞，能恢复或有依据地停止 |
| 18 子 Agent | 委派的边界是什么？ | 输入输出契约、局部上下文和工具权限；子任务失败与取消可传播；与单 Agent 基线对照 |
| 19 多 Agent 调度 | 同时工作怎样保持一致？ | 并发上限、独立工作区、冲突检测、共享预算；禁止静默覆盖，避免无限派生；记录协作额外成本 |
| 20 开发者 Agent 综合验收 | 测试通过是否等于任务完成？ | 跨文件缺陷修复；检查需求、隐藏回归、补丁范围与工作区状态；失败能从模型、工具、上下文或环境定位 |

## 阶段四：通过实验改进 Harness（21–25）

| 章 | 核心问题 | 增量成果与验收证据 |
|---|---|---|
| 21 评测平台 | 如何公平比较不同实现？ | 任务、环境、运行器、评分器分离；开发集与独立测试集、批量运行和版本记录；不能通过修改测试冒充成功 |
| 22 评分器 | 自动评分本身可靠吗？ | 确定性结果检查、评分规则及模型评分器与人工样本校准；分析误判、位置偏差与评分器受注入影响 |
| 23 消融与统计 | 改动提升还是随机波动？ | 固定任务与预算，多次试验、配对比较、区间和失败分类；一次只改变可解释变量，不用开发集提升冒充泛化 |
| 24 模型适配与性能 | 瓶颈来自模型还是系统？ | 至少两种实际可用模型配置的受控对照；适配工具与推理消息差异，分析首响应、工具等待、吞吐、用量及预算 |
| 25 模型与 Harness 协同 | 如何把失败变成改进信号？ | 从轨迹生成带来源的失败分类与候选训练样本，介绍 SFT、偏好与 reward/rollout 接口；区分 Harness 改动收益与模型变化，不把样本导出当训练收益 |

## 阶段五：迁移、交付与独立研究（26–32）

| 章 | 核心问题 | 增量成果与验收证据 |
|---|---|---|
| 26 浏览器迁移 | 动态界面怎样可靠操作？ | 操作本地演示站，比较 API、DOM 与截图观察；应对元素变化、陈旧页面和操作结果不明，验证真实页面状态 |
| 27 资料研究与数据分析 | 没有单一答案时如何核验？ | 固定资料与合成数据库上的证据报告；先检索基线再比较语义检索；校验引用、聚合和访问范围，多模态材料可追溯 |
| 28 企业操作迁移 | 外部副作用如何可靠执行？ | 接入预置订单与工单 API，校验身份、审批、幂等和响应丢失；用数据库状态验收，共用核心运行时 |
| 29 产品与部署 | 别人如何理解和控制运行？ | 简单交互与轨迹查看、人工接管、配置诊断、发布和回归；新环境可启动、重置与排错 |
| 30 源码与开源维护 | 如何理解并改进成熟系统？ | 精读固定版本相关调用链、最小运行验证、一次维护任务和设计记录；上游 PR 可作作品，合并与否不作为课程门槛 |
| 31 独立毕业项目 | 能否迁移到未讲过的需求？ | 学习者定义需求、架构、风险与验收，AI 实现；复用核心并接受未知故障测试，提交复现说明与技术答辩 |
| 32 研究进阶（选修） | 如何检验一个新的 Harness 假设？ | 复现一项研究，完成消融与保留测试集评估；可探索自动改进 Harness，但限制搜索预算和可修改范围，报告负结果 |

## 毕业验收

必修终点为第 31 章；研究方向另完成第 32 章，并按需要补充 Python、实验统计与后训练知识。章节数量不是能力等级。

- 同一核心运行时支持开发者 Agent 与三类迁移练习，业务逻辑不侵入核心。
- 确定性安全与状态一致性检查全部通过；明确实际隔离平台与未支持边界。
- 提交至少 30 个独立任务的初始任务集，覆盖正常、缺失信息、工具失败、权限、恢复和迁移；其中至少 10 个在策略冻结前不用于调优。该数量是课程起点，不足以支撑普遍性能结论。
- 模型比较与关键策略消融在共同任务上重复运行，报告样本数、重复次数、实际费用及不确定性；样本或预算不足时明确限制，不声明统计显著提升。
- 至少三份技术记录：恢复故障诊断、上下文策略实验、单/多 Agent 对照。结果没有提升同样可以合格，关键是方法与证据。
- 学习者能解释完整执行链，提出可区分的故障假设、选择观测点，并说明 AI 修复为什么成立；代码和实验仍由 AI 编写。

## 每个小步的教材结构

目标与可观察任务 → 前置知识和精确起点 → 原理与执行轨迹 → AI 增量实现和差异 → 正常与失败验证 → 少量源码对照 → 理解检查和复盘。

公开读者能取得每步起点及结果，依赖与环境绑定版本。不得一次生成后续全部 Agent 功能。练习环境由课程维护者提前准备，按章提供最小接口；实现细节放附录。

离线回放验证程序行为，真实调用验证模型交互，两者分别标注。第一章真实调用前确认可用 API 与预算；不绑定唯一付费厂商。课程不承诺招聘结果或任意任务可靠完成，招聘描述仅作为外部参照。
