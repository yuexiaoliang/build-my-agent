# 渐进式课程蓝图 v0.1

状态：设计稿。表格给出章节规格，不是已经完成的详细教材。完整章节按阶段编写，经练习验证后发布。

## 学习目标与主线

学习者能判断新需求是否适合 Agent，理解工具和状态设计，指导 AI 实现、验证和调整系统。学习阶段及毕业项目的代码均可由 AI 编写；独立能力指能提出需求、读懂关键实现与执行过程、判断结果并指导修改，不要求脱离 AI 编程。主线采用 TypeScript，面向有开发经验的中文读者，另设预备篇。

贯穿项目：模拟企业的订单异常与售后 Agent。输入例如“订单延迟，请查明原因并按政策处理”。系统检索政策、查询订单和物流、生成有证据的方案、申请审批、执行获批操作并更新工单。数据与外部动作全部在本地模拟环境中。

最初只提供 CLI。Web 交互放在部署阶段；数据模型和普通业务后台不作为必修作业。明确规则用确定性代码，Agent 负责需要语言理解、信息整合和动态选择的部分。

## 章节规格

预备篇按诊断结果选读：TypeScript 类型与异步、HTTP/JSON、Git、测试、环境变量。能跟随 AI 的示例理解一次 API 请求的输入、输出和失败原因即可进入主线，无需自行编写测试。

下表的实现产出与测试代码由 AI 按章、按小步完成。验收证据分为两部分：AI 运行测试并展示证据；学习者结合讲解理解关键代码、执行过程和结果。每章可以包含多个小步，不能一次生成整章之后的完整系统。

| 章 | 核心问题 | AI 增量实现产出 | 验收证据 |
|---|---|---|---|
| 01 任务与模型 | 聊天、固定工作流和 Agent 如何区分？ | 对三类需求分类；完成一次真实模型调用和离线回放 | 能解释选型；正确处理缺失配置和请求失败 |
| 02 工具调用 | 模型如何请求执行函数？ | 一个本地订单查询工具与参数校验 | 参数错误、未知订单不会被当成成功 |
| 03 运行循环 | 如何把行动结果用于下一步？ | 模型→工具→观察循环，调用 ID 关联与步数上限 | 两步任务可完成；循环有界；工具结果正确关联 |
| 04 协议与上下文 | 怎样处理结构化输出、多轮和上下文预算？ | 消息层、结构化结果校验、上下文裁剪 | 无效 JSON、截断输出和指代缺失得到明确处理 |
| 05 最早的评测 | “跑通一次”说明了什么？ | 离线轨迹测试、工具调用断言和小型真实模型评测集 | 同一用例可回放；报告成功数、总数和失败原因 |
| 06 接入企业 API | 本地工具如何变成远程操作？ | 类型化 API 适配层、身份传递和错误分类 | 401/403、404、超时与业务失败被区分 |
| 07 检索与证据 | 如何根据企业政策回答？ | 先关键词基线，再加入语义检索与引用 | 找不到依据时不编造；引用确实支持建议 |
| 08 记忆与隔离 | 会话、长期记忆、任务状态有何不同？ | 会话持久化、可更新和删除的业务偏好记忆 | 重启保留会话；不同用户/租户的数据不串读 |
| 09 工具权限 | 哪些输入可信，哪些操作允许？ | 工具最小权限、提示注入测试、日志脱敏 | 恶意政策文本不能扩大权限或暴露其他客户数据 |
| 10 规划与工作流 | 什么时候让模型决定，什么时候固定步骤？ | 订单异常处理计划与显式状态流 | 缺失信息先澄清；同一任务与固定流程基线对比 |
| 11 人工审批 | “模型说批准了”为什么不够？ | 持久化审批请求与人工处理入口 | 未授权身份不能批准；修改动作参数须重新审批 |
| 12 可靠执行 | 中断后重试会不会重复产生副作用？ | 恢复机制、幂等键和结果核对 | 写成功但响应丢失、重启后恢复均不重复执行 |
| 13 可观测与成本 | 如何定位失败和衡量改进？ | 运行轨迹、耗时/用量统计、取消和预算限制 | 从轨迹区分检索、模型、工具失败；比较改动前后表现 |
| 14 MCP 与协作 | 标准工具接入和子任务是否值得增加？ | 同一只读工具的 MCP 接入；一个有边界的子任务 | 工具权限不扩张；单/多 Agent 对比成功率、耗时和用量 |
| 15 框架对照 | 框架替我们承担了什么？ | Mastra 重做一条流程；Deep Agents JS 小型编排实验 | 共用业务 API 和评测集；说明收益、缺点和适用场景 |
| 16 交付 | 怎样让别人运行和维护？ | 简单交互入口、配置说明、部署与回归检查 | 新环境可启动、重置、执行样例并检查数据库结果 |

每章原则上引入一个主要概念；遇到双主题负担过大时拆为短课，不临时要求学习者开发新业务模块。评测第 05 章就开始，后续每章追加用例。

## 迁移实验与毕业考核

迁移实验安排在核心工程章节后，每个限定任务范围，重点复用而非另写一套平台：

- 编程 Agent：在隔离的练习仓库修复一个缺陷，以测试结果判定成功，阅读 mini-swe-agent 的核心循环。
- 浏览器 Agent：操作本地演示页面，处理元素变化和页面异常；比较 API 与浏览器工具的适用性。
- 数据分析 Agent：只读查询合成数据库，验证聚合结果与访问范围。
- 多模态：读取合成截图/单据，用字段与来源校验结果；需要支持图片的模型，单独标注成本和前置条件。

毕业项目由学习者在开题阶段提出一个新的业务需求，不沿用订单异常题目。AI 继续承担代码、测试和运行说明的编写；学习者主导需求、讨论架构取舍、理解关键工具与状态、依据证据判断结果，并提出修改要求。逐步减少的是导师对任务拆解的引导，不是 AI 编码支持。

共同验收标准：能处理正常任务、缺失信息、工具失败、权限拒绝；涉及写操作时验证审批、重复请求和中断恢复。至少 20 个有预期结果的用例，包含上述失败路径；确定性权限与数据隔离检查必须全部通过。真实模型效果报告实际成功率、样本数、模型配置和限制，不以一次演示代替效果结论。

## 每章完整教材的统一结构

1. 场景与目标：本章结束时能做什么，先给可观察的验收任务。
2. 前置知识与起点：精确起始代码版本、数据场景和运行方式。
3. 原理与执行过程：用一个最小例子跟踪输入、模型输出、工具和状态。
4. AI 增量实现：说明本步改动及原因，只编写当前概念需要的代码；展示相对上一步的差异、关键函数与输入输出，不留必须由学习者填写的 TODO。
5. 验证与排错：AI 编写并运行必要检查，展示正常路径、失败路径、日志与业务状态；带学习者将观察结果对应到代码。
6. 源码对照：少量固定提交的入口，围绕具体问题阅读。
7. 理解检查与复盘：请学习者用自己的话描述执行过程，或预测条件变化后会发生什么；随后由 AI 实现变化并验证。疑问先在本步解决，不以手写代码作为通关条件。

每个小步保留可运行检查点和配套说明，公开读者可以直接查看该步代码与差异。章节说明当前已实现的能力和下一步要解决的问题；不为未来章节预先搭建复杂抽象。模拟企业基础设施可以提前准备，但学习中的 Agent 功能严格随课程增加。

## 公开学习的设计约束

基础练习有不消耗 API 的回放模式，但明确其不能验证真实模型能力。真实调用使用环境变量配置，不提交密钥，不把某个付费厂商绑定为唯一学习入口；第一章编写时验证至少一个实际可用的模型配置。

主线发布前，模拟业务系统稳定；每章绑定兼容版本与独立种子数据。读者无需阅读业务系统内部实现。中文教材配英文术语表，后续翻译不复制维护两套示例代码。

课程不承诺模型可以可靠完成任意任务；独立能力包括识别不可行需求、采用普通工作流、收缩自动化边界以及设计人工交接。
