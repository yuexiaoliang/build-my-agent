# 教学环境约定

状态：准备阶段的边界设计，不是已实现的 API 文档。

## 核心原则

模拟企业系统提前备齐，按章节逐步介绍接口。学习者主线代码只集中在 Agent、工具适配、状态处理与评测；业务系统开发放在选修附录。

系统使用 TypeScript HTTP 服务与 SQLite、本地合成数据。CLI 是最早的交互入口，简单审批与结果查看界面在需要时提供。默认不要求 Docker，跨平台启动方案在实现时验证。

## 最小业务范围

提供客户、订单、物流、政策文档、工单和审批记录。围绕一条“订单延迟→核实→建议→审批→模拟执行→更新工单”的链路设计，不扩展支付网关、真实发货、完整 CRM 或 ERP。

只读能力包括查询订单、物流、工单和政策；写能力包括创建工单、提交处理申请和执行获批的模拟补偿。审批使用独立的人类角色；Agent 不持有审批人的凭证。

业务服务验证身份、资源归属、审批状态和操作约束，提供幂等操作与审计记录。教学中不能把隐藏工具或系统提示词等同于权限控制。

## 与 Agent 的边界

学习者通过稳定 HTTP 契约接入，工具层负责参数映射与错误转换。业务系统不调用模型、不依赖课程运行时。评测通过受控的检查接口或测试数据库读取实际结果，不能仅凭 Agent 最后一句话判断成功。

同一业务服务供 AI 随课构建的基础 Agent、框架版本和毕业前对照实验使用。MCP 章节只改变工具接入方式，不重新实现业务规则。

## 数据与故障场景

每章能独立加载种子数据并重置。预备场景包含正常订单、未知订单、缺失物流、不同租户资源、政策无答案、权限拒绝、超时，以及“写入成功但响应丢失”。故障注入属于教学控制入口，不暴露给 Agent。

重置只作用于本项目的本地教学数据。应用启动默认绑定本机；公开部署前才单独设计真实身份管理和环境隔离。

## 面向学习者的发布门槛

- 在 Windows、macOS、Linux 验证文档中的安装、启动、加载场景与重置流程，明确验证平台及版本。
- 提供精简 API 说明、样例请求和错误解释；完整内部实现无需阅读。
- 确定性契约测试覆盖权限、审批、幂等与故障场景，不依赖付费模型。
- 固定业务契约版本，每章注明兼容版本；框架或教材升级不能悄悄改变练习数据与预期结果。
- 将演示身份、合成数据和真实生产能力明确区分；发布说明不把教学模拟系统描述为可直接用于企业生产。

目前尚未实现或验证上述服务。下一阶段先定义最小业务契约与种子场景，再实现基础设施；不向学习者分配这些维护工作。
