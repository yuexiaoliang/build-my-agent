# 03.3 · 多工具请求的顺序与 ID

> **本步问题**：一次响应里带多个 `tool_calls` 时，Harness 按什么执行、按什么回填——顺序重要吗？
> **前置**：03.1 id 关联与回填；03.2 有界循环（并发请求已出现过一次）。
> **蓝图对应**：第 03 章 Agent Loop（模型行为的边界处理）。

## 1. 目标与可观察任务

模型在一轮里请求多个工具是合法且常见的：03.2 收录的运行里两次是"每轮一个工具"，另一次第 1 轮就**同时**发出两个请求（录制被同路径复跑覆盖，未留档）。同一任务为什么形状不同、Harness 该怎么接，本步把它测清楚：

- 看清线上响应的形状：每个调用带 `index`（位置标号）与 `id`（关联键）；
- Harness 逐个执行、逐个回填，顺序保持数组序；
- 运行时能观察到：一轮里两个 `index=0/1` 的请求 → 两条 tool 消息 → 下一轮模型同时用到两份结果。

## 2. 原理与执行轨迹

线上响应里的多工具形状：

```json
"tool_calls": [
  { "index": 0, "id": "call_…A", "type": "function",
    "function": { "name": "read_file", "arguments": "{\"path\": \"notes.txt\"}" } },
  { "index": 1, "id": "call_…B", "type": "function",
    "function": { "name": "read_file", "arguments": "{\"path\": \"todo.md\"}" } }
]
```

- `id` 是回填时的关联键——03.1 已证明缺配对会被服务端 400 拒绝。
- `index` 是位置标号：非流式响应里就等于数组下标；它的主战场是流式分片重组（08 章）。
- "tool 消息是否必须与请求同序"不靠猜：本步用一个颠倒顺序的实验来回答（见验证）。

## 3. 实现与差异导读

- `src/model.ts`：`ToolCall` 增加 `index?`；`readToolCalls` 读取该字段（缺省时回落到数组下标）。
- `src/cli.ts`：工具请求播报与 replay 输出加上 `index=…`，让线上字段直接可见；执行与回填顺序保持数组序（与 index 一致）。

## 4. 验证

真实运行（有费用）：

```bash
node src/cli.ts ask --tools --record fixtures/ch03/multitool.json \
  "同时读取 sandbox/notes.txt 和 sandbox/todo.md（一次发起两个 read_file 请求），然后各用一句话总结"
```

预期观察：第 1 轮两个 `tool_calls`（`index=0/1`）→ 两条 tool 消息按序回填 → 下一轮模型同时用到两份文件内容。

**预测题（先写下判断，下一轮再跑）**：如果把两条 tool 消息**颠倒顺序**发出去（`id` 不乱、只换位置），你预测服务端会怎么反应？

- A. HTTP 400 拒绝——顺序被强制
- B. 接受，模型仍能正确对应两份结果
- C. 接受，但模型把两份结果对调

离线回放（免费）：

```bash
node src/cli.ts replay fixtures/ch03/multitool.json
```

失败路径：颠倒顺序实验（上面的预测题）；未执行清单仍由 03.2 的步数上限兜底。

**颠倒顺序实验（2026-09-15，真实运行）**

```bash
node scripts/reversed-tool-messages.ts
# 读入 fixtures/ch03/multitool.json，本地重放两个 read_file，再把 tool 消息颠倒后发出
```

```text
发送的 tool 消息顺序（已颠倒，id 未变）：
  tool → call_01_DoVbK9cxpGMy8Gt5V4kU1686（85 字符）
  tool → call_00_3zBT7dys3VrtTIktm1BY3353（76 字符）

HTTP 200：服务端接受了颠倒顺序
模型回答：分别总结 notes.txt 与 todo.md —— 对应正确（没有把两份内容对调）
```

要点：**顺序不参与判分**——关联由 `tool_call_id` 决定，位置只是排布。反过来，"缺 id 配对"会被 400（03.1 的孤儿实验），两个实验合起来框出校验边界：**服务端强制的是"每个结果都有出处"，不是"出处按顺序排"**。边界声明：只验证了当前提供商与非流式响应；流式分片与第 24 章的其他提供商需要另行复核。fixture：`fixtures/ch03/multitool-reversed.json`。

## 6. 小结

`id` 决定"谁是谁"，`index` 描述"第几个"；两个字段各管一段。重复调用（模型原地打转）属于另一个问题，放在 03.4。
