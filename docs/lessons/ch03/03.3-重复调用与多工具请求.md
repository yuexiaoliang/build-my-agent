# 03.3 · 重复调用与多工具请求（主干，实施前细化）

> **本步问题**：循环里冒出的两种模型行为怎么处理——同一个调用被反复请求、一次请求里带多个工具？
> **前置**：03.1 回填与 id 关联；03.2 有界循环（重复标记只是观察，没有处理）。
> **蓝图对应**：第 03 章 Agent Loop（"重复调用有明确结果"是本章验收点之一）。

## 1. 目标与可观察任务（计划）

- **重复调用**：检测与之前某轮完全相同的 `工具名(参数原文)`，给 Harness 一个明确的处理动作；运行输出里能分辨发生了什么。
- **多工具请求**：一次响应带多个 `tool_calls` 时，确认顺序语义（响应里的 `index` 字段）、逐个执行与回填，验证 id 一一对应、服务端接受（不存在"消息顺序对不上"的 400）。

## 2. 原理与设计空间（计划）

调用签名 = 工具名 + 参数原文。重复调用通常意味着模型在原地打转，或它不认可上次拿到的结果；每次都白白消耗 03.2 的步数与费用上限。

候选处理（本步选一种并写清理由）：

| 策略 | 行为 | 风险 |
|---|---|---|
| 照常执行 | 不区分（当前实现） | 浪费轮数；将来对写工具等于重复副作用 |
| 回填提示 | 结果里注明"这与第 k 轮相同"，仍回填 | 简单；模型可能仍不改变行为 |
| 拒绝重复 | 不执行，回填"已拒绝：与第 k 轮重复" | 强硬；若环境已变化（未来有写工具时）可能误伤 |

多工具请求的结构点：线上响应里每个调用带 `index`；回填时每个 `tool_call_id` 对应一个 tool 消息，顺序以 id 关联为准，不依赖数组下标。这不是假想场景——03.2 的多步运行里模型第 1 轮就并行请求了两个工具（`fixtures/chat-2026-09-15-loop-multistep.json`），服务端接受了两个 tool 消息的回填。
