# 03.4 · 重复调用与策略（主干，实施前细化）

> **本步问题**：同一个调用被反复请求时，Harness 应该怎么办——"有明确结果"具体是什么？
> **前置**：03.2 的重复标记（只观察，不处理）；03.3 多工具请求。
> **蓝图对应**：第 03 章 Agent Loop（"重复调用有明确结果"是本章验收点之一）。

## 1. 目标与可观察任务（计划）

- 用一条会**诱导重复**的提示词拿到真实重复调用（例如"读取 notes.txt 两次并确认两次结果一致"）。
- 按选定的策略处理，运行输出可区分"首次执行 / 重复出现"。
- 步数上限（03.2）仍是最后防线；重复处理是它前面的一道更早的防线。

## 2. 原理与设计空间（计划）

调用签名 = 工具名 + 参数原文。重复调用常见于：模型不认可上次结果、参数总不对导致重试、原地打转。每次重复都白耗步数与费用（每轮都重发全部历史）。

候选策略（本步选一种，写明理由与代价）：

| 策略 | 行为 | 风险 |
|---|---|---|
| 照常执行 | 不区分（当前实现，只有标记） | 浪费轮数；对写工具等于重复副作用 |
| 回填提示 | 结果里注明"这与第 k 轮相同"，仍回填 | 简单；模型可能仍不改变行为 |
| 拒绝重复 | 不执行，回填"已拒绝：与第 k 轮重复" | 强硬；将来有写工具时，环境可能已变化 |
| 连续重复即停止 | 同一调用重复 N 次则提前结束循环 | 保护强；可能过早终止合法重试 |

**设计题（留给学习者先作答，再实现）**：面对一次完全相同的重复请求，你选择哪种策略？为什么？失败时会表现成什么样？
