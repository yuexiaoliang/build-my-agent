# 01.3 · 离线回放

> **本步问题**：怎样在没有网络和密钥的情况下，验证程序对模型响应的处理？
> **前置**：01.2 第一次真实模型调用（同目录讲义）。
> **蓝图对应**：第 01 章 任务与模型（增量成果：明确标注的离线回放）。
> 说明：讲义基础设施建立晚于本章，本页在完成后据当时的真实运行证据回填整理；代码快照见提交 `0fada09`（`课程(01.3)`）。

## 1. 目标与可观察任务

`ask --record <文件>` 把一次真实交互落盘成 fixture；`replay <文件>` 用固定响应驱动**同一条解析路径**——不联网、不读密钥。输出里【真实调用】/【离线回放】分别标注，一眼可辨。

## 2. 原理与执行轨迹

**回放 = 把响应存成数据、替换"响应从哪来"，解析路径一行不改。**

fixture 的结构是**信封 + 原文**：

- 信封（我们定义的客户端事实）：录制时间、耗时、状态码、请求内容、会话 ID。这些**不在厂商响应体里**，只有客户端能观测，必须自己记录。
- 原始响应体：原样文本，一个字节都不改。

被否掉的方案：把 `content`、`usage` 归一化后存进 fixture。两个问题——

1. 那等于拿被测代码的输出当输入：回放永远走不到"厂商原文 → 内部结构"这段解析代码，等于没测。
2. 抹掉了厂商之间的协议差异（第 04 章的主题）。厂商差异由解析层处理，fixture 保持"事实"。

两条纪律：

- **失败也要录**：录制发生在解析之前，401 这类错误一样可以回放，不必再次花钱触发。
- **能力边界要说清**：回放能证明协议解析、错误分类、状态更新；不能证明模型能力与真实可用性。所以两种模式必须在输出中分别标注。

## 3. 实现与差异导读

- `src/model.ts`：拆成 `sendChatRequest`（网络那半段）与 `parseChatResponse`（解析那半段，纯函数）——回放就是绕过前者、直驱后者。
- `src/fixture.ts`：`writeChatFixture` / `readChatFixture`（含结构校验，拒绝不符合约定的文件）。
- `src/cli.ts`：`ask [--record <文件>]`、新增 `replay <文件>` 与 `config` 子命令。

## 4. 验证

真实运行并录制（有费用）：

```bash
node src/cli.ts ask --record fixtures/ch01/ask-success.json "用一句话解释：什么是 Agent 的离线回放？"
```

离线回放（免费，不联网）：

```bash
node src/cli.ts replay fixtures/ch01/ask-success.json
```

**预测题（先写下判断，再运行）**：回放时故意把 `MODEL_BASE_URL` 指向 `127.0.0.1:9`（一个不可能连通的地址），回放会失败吗？为什么？

失败路径：`node src/cli.ts replay fixtures/ch01/model-not-supported.json`（401 录制）；`node src/cli.ts replay fixtures/ch01/malformed-response.json`（手工构造的损坏响应）。

## 5. 验证记录（回填）

1. 真实调用并录制：332 tokens，4267 ms，落盘 2.4 KB（`fixtures/ch01/ask-success.json`）。
2. 回放成功 fixture：输出与真实调用一致，明确标注【离线回放】。
3. 预测题实测：base URL 指向 `127.0.0.1:9` 回放**仍然成功**——证明回放不读配置、不联网。
4. 回放 401 fixture（`fixtures/ch01/model-not-supported.json`）：HTTP 401 + 服务端原文，退出码 3。
5. 回放损坏 fixture（`fixtures/ch01/malformed-response.json`，响应体里故意用了单引号）：`响应不是合法 JSON`，退出码 4。
6. 安全检查：录制文件不含 `authorization` / `bearer` 字样（grep 计数 0）——信封只存客户端事实，密钥不落盘。

设计落差记录：当时曾提议用自定义 schema 存 `content`、token 统计、耗时、模型名以兼容多家 provider。容器思路正确（客户端事实必须自存），但 `content` 与 `usage` 是**解析结果**，不能进 fixture——否则回放跳过被测代码，还抹掉协议差异。

## 6. 小结

fixture 是"事实"不是"解析结果"；回放验证程序行为，真实调用验证模型交互，两者分别标注。未决问题留给后面：流式响应怎么回放（第 08 章）；fixture 变多后的组织与命名（见 `fixtures/INDEX.md`，第 05 章评测再深化）。
