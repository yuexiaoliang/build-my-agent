# 04.3 · 响应校验分级

> **本步问题**：响应字段缺失或畸形时，哪些可以规范化容忍，哪些必须拒绝？界线画在哪？
> **前置**：04.1 的现状表（目前几乎全部容忍）；02.3 的工具参数校验（工具侧已有"拒绝"的先例）。
> **蓝图对应**：第 04 章（"结构化输出校验""不把损坏输出当成功"）。

## 1. 目标与可观察任务

- 产出一张**校验分级表**：每个可疑字段 → 容忍（归一化）/ 拒绝（`ModelResponseError`，带字段定位）+ 理由。学习者主导定级，AI 评估后实现。
- `parseChatResponse` 按表收紧；`npm run check` 与 `npm run check:tools` 回归。
- 手术 fixture 集验证每类缺陷的真实走向，全部离线回放、零费用。

## 2. 原理与执行轨迹

校验分级的两难：

- **全容忍**（现状）→ 静默误解析（silent misparse）——最危险的失败形态：不报错，但程序状态全错。
- **全拒绝** → 协议有小异动的提供商全部不可用；04.1 已见 `content: null` 是真实提供商会发的形状。

判断线索（课堂讨论用）：这个字段下游谁在用？填 `""` 之后下游**能不能自己发现**？

- `name` 填 `""` → 02 章闸门会拦（`未知工具：`）——错误被**推迟**且换了含义：明明是响应损坏，报成了"模型请求了未知工具"。
- `id` 填 `""` → 03 章的 id 配对语义被破坏，但回填时没有任何报错——错误**静默**。
- `arguments` 填 `""` → 02 章闸门拦（`参数不是合法 JSON`）——同样被推迟、换含义。

新术语：**失败等级**——按"多快被发现、以什么面目被发现"分级：

| 等级 | 表现 | 评价 |
|---|---|---|
| 响亮失败（loud failure） | 当场报错，原因指向真实病根 | 目标形态 |
| 延迟失败（deferred failure） | 下游才炸，报错含义已变 | 可接受但有代价 |
| 静默误解析（silent misparse） | 不报错，状态全错 | 必须消灭 |
