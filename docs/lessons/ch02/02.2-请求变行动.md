# 02.2 · 请求变行动

> **本步问题**：模型请求的工具调用如何真正执行？
> **前置**：02.1 工具请求的协议形状。
> **蓝图对应**：第 02 章 工具契约。
> 说明：讲义基础设施建立晚于本章，本页在完成后据当时的真实运行证据回填整理；代码快照见提交 `e887207`（`课程(02.2)`）。

## 1. 目标与可观察任务

`ask --tools` 现在会真正执行模型请求的工具并把结果打印到终端。运行时能观察到：一轮调用里"请求 → 执行 → 打印"三段；以及一个关键事实——**模型看不到执行结果**，行动发生了，闭环还没建立（那是第 03 章的循环）。

## 2. 原理与执行轨迹

- 执行器契约束得很小：`executeToolCall(name, argumentsText) → string`——它不认识响应结构，只认"名字 + 参数原文"。
- `argumentsText` 在模型层保持原文，到**执行时**才 `JSON.parse`：解析、校验、执行各管一段，谁也不越界。
- sandbox 根锚在**代码位置**（`import.meta.url`），不依赖进程当前工作目录——路径基准是一条设计决策：工具的行为不该随"从哪个目录启动"而变化。
- 无参工具（`list_files`）的 `arguments` 是空对象 `{}`；执行器直接忽略参数。
- **本步刻意不做校验**：未知工具抛错、`../` 路径不被拦截（`join` 语义，从代码可读）。这是增量边界——先把"执行"做真，02.3 再装闸门，用真实运行对照前后差别。

## 3. 实现与差异导读

- `src/tools.ts`：`sandboxRoot`（用 `import.meta.url` 锚定到仓库的 `sandbox/`）；`executeToolCall`——switch 分发，`read_file` 读文件、`list_files` 列目录。
- `src/cli.ts`：ask 分支增加"请求 → 执行 → 打印结果"段；回放分支仍然**不执行**——回放只走解析路径（01.3 定下的模式分工）。

## 4. 验证

真实运行（有费用）：

```bash
node src/cli.ts ask --tools "sandbox/todo.md 里有什么？"
node src/cli.ts ask --tools "sandbox 目录里有哪些文件？"
```

**预测题（先写下判断，再回答）**：执行结果打印之后，模型看到结果了吗？它能不能接着用结果做事？（提示：回想 01.2——一次调用就是一次独立 HTTP 请求。）

离线对照（免费）：`node src/cli.ts replay fixtures/ch02/toolcall.json`——同样的工具请求，回放永远不执行。

失败路径（本步故意不处理，留作观察）：让模型请求未知工具会抛 `未知工具：xxx`；请求 `read_file` 读 `../package.json` 在代码层面会逃出 sandbox——两者在 02.3 变成可观察、可分类的拒绝。

## 5. 验证记录（回填）

全部为真实运行：

1. `ask --tools "sandbox/todo.md 里有什么？"` → `read_file` 执行，输出文件内容（426 tokens）。
2. `ask --tools "sandbox 目录里有哪些文件？"` → `list_files` 执行，输出 notes.txt、todo.md（390 tokens）。
3. 预测题结论：结果只打印在本机终端，**模型看不到**——下一轮请求不会自动带上它。这正是 03.1 要解决的问题。

## 6. 小结

"请求 → 行动"只差一个最小执行器，但有两个刻意留下的开口：没有校验（任何人可请可执行）和没有回填（模型看不到结果）。下一小步先列出"必须拒绝"的清单，再把校验闸门装上。
