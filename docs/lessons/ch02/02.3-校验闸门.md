# 02.3 · 校验闸门

> **本步问题**：哪些请求必须拒绝，拒绝长什么样？
> **前置**：02.2 请求变行动（无校验执行的两个开口）。
> **蓝图对应**：第 02 章 工具契约（参数、路径与未知工具校验；无效请求不执行）。
> 说明：讲义基础设施建立晚于本章，本页在完成后据当时的真实运行证据回填整理；代码快照见提交 `480b790`（`课程(02.3)`）。

## 1. 目标与可观察任务

执行之前先过闸门：合法请求照常执行；非法请求**拒绝且不执行**，打印拒绝原因并以专用退出码（6）结束。新增 `call` 子命令，离线直调"校验 → 执行"管线，不经过模型——验证闸门不用花 API 费用。

## 2. 原理与执行轨迹

**闸门站在执行之前**：`checkToolCall(name, argumentsText)` 先判，`executeToolCall(name, args)` 只在通过后运行。"无效请求不执行"是结构保证，不是纪律——执行器根本接触不到未校验的参数。

五道判断，顺序即优先级：

| 顺序 | 检查 | 拒绝示例 |
|---|---|---|
| 1 | 未知工具 | `delete_all` |
| 2 | 参数是合法 JSON | `not-json` |
| 3 | 参数是对象 | `[1]` |
| 4 | schema：必填与类型 | 缺 `path`、`path` 是数字 |
| 5 | 路径边界 | `../package.json`、`/etc/hosts` |

两个设计决策：

- **路径边界用 `resolve` + `relative` 判定，不用字符串前缀比较**：`startsWith(sandboxRoot)` 会放行 `/sandbox-evil` 这类兄弟路径；`relative` 的结果越界时以 `..` 开头，语义直接可读。
- **拒绝是"结果"，不是异常**：走正常输出 + 专用退出码 6，而不是抛出崩溃。这为第 03 章"把拒绝原因回填给模型、让它自我纠正"留出了形状。

**已知边界**：闸门是**词法检查**——符号链接可以绕过（实测通过 `sandbox/__probe -> ..` 读到了仓库根文件）。物理路径校验（realpath）留给第 06 章。

## 3. 实现与差异导读

- `src/tools.ts`：新增 `checkToolCall`（返回 `ToolCheck`：ok / reason），内部依次调用 `checkAgainstSchema`（按工具定义里的 schema 检查必填与类型）与 `resolveInSandbox`（resolve + relative 判定）；`executeToolCall` 改为只接受已校验的 `args`。
- `src/cli.ts`：新增 `call <工具名> "<参数JSON>"` 子命令（离线直调管线，拒绝退出码 6）；ask 分支逐条请求"检查 → 执行或拒绝"。

## 4. 验证

设计题（先列清单，再跑命令对照）：哪些请求必须拒绝？至少覆盖机制层（名字、参数）与边界层（操作 sandbox 以外的文件）。

离线直调（免费）：

```bash
node src/cli.ts call read_file '{"path": "notes.txt"}'      # 合法
node src/cli.ts call read_file '{"path": "../package.json"}' # 越界
node src/cli.ts call read_file '{"path": "/etc/hosts"}'      # 绝对路径
node src/cli.ts call read_file '{"path": 123}'               # 类型错
node src/cli.ts call read_file '{}'                          # 缺必填
node src/cli.ts call read_file 'not-json'                    # 非 JSON
node src/cli.ts call delete_all '{}'                         # 未知工具
node src/cli.ts call list_files '{}'                         # 合法无参
```

真实运行（有费用）：`node src/cli.ts ask --tools "sandbox/notes.txt 里写了什么？"`——过闸门后正常执行。

失败路径：上面的离线命令大半就是失败路径本身；另有一条已知边界演示——`ln -s .. sandbox/__probe` 后经符号链接读取仓库根文件，观察词法检查被绕过。

## 5. 验证记录（回填）

全部为真实运行（`call` 直调 + 一次真实调用）：

1. 合法 `notes.txt` → 执行，退出码 0。
2. `../package.json` → 拒绝（路径越界），退出码 6。
3. `/etc/hosts`（绝对路径）→ 拒绝，退出码 6。
4. `path` 为数字 → 拒绝（应为字符串），退出码 6。
5. `{}` → 拒绝（缺少必填参数 path），退出码 6。
6. `not-json` → 拒绝（参数不是合法 JSON），退出码 6。
7. `delete_all` → 拒绝（未知工具），退出码 6。
8. `list_files` → 执行，退出码 0。
9. 符号链接探测 → **绕过成功**（读到仓库根文件）——已知边界，第 06 章修。
10. 真实调用（问 notes.txt）→ 过闸门后正常执行，414 tokens。

设计输入：拒绝清单中"操作 sandbox 以外的文件必须拒绝"来自课堂提出并验证成立；机制层三类（未知工具 / JSON / schema）由课程补全。记录在案的取舍：多余参数目前忽略不拒绝；文件不存在（ENOENT）属环境失败而非非法请求，仍走通用错误——分类留待第 11 章。

## 6. 小结

闸门让"无效请求不执行"成为结构保证：五道检查按序执行，拒绝是带原因的结果。但"当时测过"不等于"以后仍对"——下一小步把这些判断固化成可重复跑的证据矩阵，再配一次"骗过闸门"的对抗练习。
