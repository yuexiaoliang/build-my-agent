# 学习计划 v0.1

适用：有开发经验、Agent 新手；每周 10–15 小时。代码由 AI 随课程增量编写，学习时间主要用于理解、运行观察、讨论与复盘。暂保留 16 周、约 160–240 小时作为可调整的时间预算，在前两周后根据理解节奏重新估计，不把手工编码时间计入要求。

## 阶段安排

| 周 | 内容 | 阶段成果 |
|---|---|---|
| 1–2 | 诊断与预备知识（按需）、01–03 章 | 读懂 AI 逐步实现的有界工具调用循环并解释执行过程 |
| 3–4 | 04–06 章 | 上下文和协议处理、最小评测集、接入企业 API |
| 5–6 | 07–09 章 | 有证据的政策回答、持久化会话、隔离与权限验证 |
| 7–8 | 10–12 章 | 可审批、可恢复、避免重复执行的完整业务流程 |
| 9–10 | 13–14 章 | 运行诊断、成本对比、MCP 与受限协作实验 |
| 11–12 | 15–16 章 | 框架对照及可复现交付 |
| 13–14 | 编程、浏览器、数据分析、多模态迁移实验 | 能在不同环境复用核心能力；每个实验限制规模 |
| 15–16 | 独立毕业项目与评审 | 新需求的设计、实现、评测和运行说明 |

教材与模拟系统准备属于课程维护工作，不计入学习者课时。若毕业项目扩大，或首次接触某一迁移领域，应另加时间。

## 每周节奏

- 2 小时：理解原理、预测示例执行过程。
- 5–7 小时：跟随 AI 的小步实现，阅读差异、运行观察、讨论不理解的部分。
- 2–3 小时：运行失败场景、读参考源码、比较实现。
- 1–3 小时：提出需求变体，由 AI 修改后共同验证；复盘并整理学习记录。

每次学习以 60–90 分钟为一个单元。结束时记录：完成了什么、失败证据、当前假设、下次最小行动。记录不需要长，能够恢复上下文即可。

## 如何从跟随理解走向主导实现

前段由 AI 拆解步骤、编写代码并讲解；中段让学习者先讨论输入输出和预期行为，再由 AI 实现；后段由学习者提出新需求、参与方案选择并检查结果。各阶段的代码与测试都可由 AI 编写。出现理解卡点时，AI 用更小的例子、执行轨迹或局部代码解释，不继续堆叠功能。

每个阶段检查“看懂关键代码、理解执行过程、看懂验证结果”。可以通过简短复述或一个条件变化确认理解；变体实现由 AI 完成。逐步培养提出修改要求和判断方案的能力，不要求代码默写或独自排错。多 Agent 或复杂框架没有提升时，允许保留简单方案并说明依据。

## 第一阶段教材准备清单

下一步先设计 01–03 章正文与分步讲解，在学习推进时由 AI 逐步产出对应代码、差异说明和离线测试；不提前一次写完整个阶段的 Agent。开始真实模型练习前明确可用 API 与预算，验证配置；不要求读者现在选择全部工具链或购买服务。

模拟系统另行准备，在第 06 章使用前完成启动、重置、跨平台和契约验证。当前仓库只有设计文档，以上学习周次尚未正式开始。
