# 学习计划 v0.4

面向有开发经验的 Agent 新手。AI 按当前需要增量编写代码、测试和实验；学习者理解、验证并逐渐主导设计。章节范围沿用 [课程蓝图](course-blueprint.md)，验收以 [能力矩阵](competency-matrix.md) 的证据为准，不承诺固定周期或招聘结果。

## 两条进度，不混为一个数字

**作品位置**记录代码在哪一小步、有哪些实际运行证据。**理解证据**记录某个概念能否解释、是否需要提示、能否迁移和隔课复用。作品跑通不自动提升能力状态，理解上的缺口也不抹去已有代码进度。

章节百分比仍可作为导航：01–05 约 16%，06–12 约 23%，13–20 约 26%，21–25 约 16%，26–31 约 19%；第 32 章选修单列。这只是按必修章节数量粗算，不代表工作量或掌握比例，不用它催进度。

## 能看到的阶段成果

| 位置 | 系统逐渐能做什么 | 学习者的核心判断 |
|---|---|---|
| 01–05 | 有边界的只读助手与最早回归 | 看懂完整执行链，区分停止与完成，知道证据证明什么 |
| 06–12 | 受控修改、执行、取消与恢复 | 判断权限、环境状态和副作用，设计能暴露失败的检查 |
| 13–20 | 处理大项目和较长任务 | 定位上下文/规划问题，判断委派是否值得，核验实际结果 |
| 21–25 | 用实验改进系统 | 控制变量、审查评分器、报告不确定性和成本 |
| 26–31 | 迁移、交付、独立项目 | 在 AI 给方案前提出约束和验收，审查实现和证据 |
| 32 选修 | 研究复现与新假设实验 | 给出可检验假设、消融及负结果 |

## 单次学习与补救

围绕一个主要问题，按需经过定位、完整示范、有支持的参与、反馈、变体和收口。不分配固定的讲解/编码/出题时间比例：前置欠缺就补前置，已有证据就减少示范；不以章节号强制撤掉帮助。

同一例子多次卡住时换对照或示范，不增加题量。概念不影响当前步的安全与理解时可以带着待复核项继续；真正的前置缺口先补最小连接，不要求重做整章。

复习嵌入下次恢复、下一次使用该概念、阶段验收三个自然位置。每次只选当前最有价值的一个问题，不固定日历打卡。未来需要定时提醒时另行设置，不把文档计划说成已建立提醒。

## 当前记录的衔接方式

现有记录在 04.1 后、04.2 前。保留已经完成的小步、提交和 tag。导师按需用 [桥接课](lessons/bridge-01-04.md) 将消息、调用 ID、校验、执行、回填和停止串起来；随后使用重写的 [04.2](lessons/ch04/04.2-截断与finish_reason.md)。不把课程维护算作学习完成，不预填新的能力证据。

`.learning/state.md` 是恢复入口，`.learning/lessons/INDEX.md` 是回查入口。旧状态可继续使用，新证据出现时逐渐补充提示程度、范围及下一教学动作，避免一次迁移制造额外管理工作。

后续开课先完善当前材料，再实现当前功能；不在这次维护中一次生成其余章节或完整 Agent。批量真实实验前另定预算和停止条件。
